Cheese v4 combines the LEGO EV3 control system with an external vision subsystem.

The wiring architecture must connect four different types of devices:

- **controller** — EV3 Brick,
- **actuators** — Large and Medium motors,
- **LEGO sensors** — ultrasonic and color sensors,
- **external vision electronics** — Arduino Nano and HuskyLens.

The complete signal chain can be summarized as:

<p align="center">
  <strong>
    Sensors → EV3 → Navigation Logic → Motors
  </strong>
</p>

while the external vision chain follows:

<p align="center">
  <strong>
    HuskyLens → Arduino Nano → EV3 → Navigation Logic
  </strong>
</p>

The EV3 separates the robot into two primary connection groups:

| Connection Group | Purpose |
| :--- | :--- |
| **Sensor inputs** | Bring environmental measurements into the EV3 |
| **Motor outputs** | Send commands from the EV3 to the actuators |

This creates a simple control direction:

```text
Environment
    ↓
 Sensors
    ↓
EV3 Inputs
    ↓
Navigation Software
    ↓
EV3 Outputs
    ↓
 Motors
    ↓
Robot Movement
```

## ❀ 2.2.5 Motor Connections ────୨ৎ────────୨ৎ────

Cheese uses separate motors for propulsion and steering.

| Actuator | Type | Function |
| :--- | :--- | :--- |
| **Drive Motor** | EV3 Large Motor | Provides propulsion |
| **Steering Motor** | EV3 Medium Motor | Controls the front steering linkage |

Separating these functions allows the navigation software to control:

- forward/reverse movement,
- driving speed,
- steering angle,
- wall corrections,
- curve behavior,
- obstacle avoidance,
- and parking corrections.

The EV3 therefore converts navigation decisions into two independent physical outputs:

```text
                    ┌──→ Large Motor → Propulsion
Navigation Logic ───┤
                    └──→ Medium Motor → Steering
```

## ❀ 2.2.7 External Vision Interface ────୨ৎ────────୨ৎ────

The HuskyLens introduces a non-LEGO vision subsystem into Cheese.

Instead of treating the camera as a normal EV3 sensor, the system uses an **Arduino Nano as a communication bridge**.

The architecture is:

```text
HuskyLens
    │
    │ I2C
    ▼
Arduino Nano
    │
    │ USB
    ▼
EV3 Brick
    │
    ▼
Navigation Software
```

The devices have different responsibilities:

| Device | Responsibility |
| :--- | :--- |
| **HuskyLens** | Performs visual obstacle recognition |
| **Arduino Nano** | Receives and transfers vision information |
| **EV3 Brick** | Interprets the data and decides robot movement |

This separation keeps the camera-recognition subsystem modular.

## ❀ 2.2.8 Arduino Nano ↔ HuskyLens Wiring ────୨ৎ────────୨ৎ────

The HuskyLens communicates with the Arduino Nano through **I2C**.

The documented connection is:

| HuskyLens | Arduino Nano | Function |
| :--- | :--- | :--- |
| **VCC** | **5V** | Power |
| **GND** | **GND** | Common ground |
| **SDA** | **A4 / SDA** | I2C data |
| **SCL** | **A5 / SCL** | I2C clock |

## ✦ Engineering Decisions & Lessons ─── ⋆⋅☆⋅⋆ ───

### 1. One diagram was not enough

A system-level diagram is useful for understanding Cheese, but it cannot show every connection clearly.

Separating the documentation into multiple levels makes the architecture easier to reproduce.

### 2. LEGO and external electronics require a defined interface

The LEGO sensors connect directly to the EV3.

The HuskyLens does not follow the same path.

Its information follows:

> **HuskyLens → Nano → EV3**

Documenting this difference prevents confusion when reproducing the robot.

### 3. Electrical diagrams and physical photographs serve different purposes

A schematic explains **where a connection should go**.

A photograph shows **how the team actually implemented it**.

Both are useful engineering evidence.

### 4. Cable routing is part of mechanical design

Wires must not interfere with steering, wheels, sensors, or moving structural components.

Therefore, wiring decisions cannot be separated completely from mechanical design.

### 5. Modular documentation improves debugging

When a problem appears, the team can inspect the system by layer:

```text
Sensor
  ↓
Connection
  ↓
Interface
  ↓
EV3
  ↓
Software
  ↓
Motor
```

This makes it easier to determine whether a failure is caused by sensing, communication, control, or physical movement.

## ✦ 2.2 Final Wiring Summary ─── ⋆⋅☆⋅⋆ ───

Cheese v4 combines a standard LEGO EV3 control architecture with an external Arduino Nano and HuskyLens vision subsystem.

The EV3 remains the central controller.

The LEGO sensors and motors connect through the EV3 architecture, while obstacle-vision information follows a separate communication path:

<p align="center">
  <strong>
    HuskyLens → I2C → Arduino Nano → USB → EV3
  </strong>
</p>

The electrical architecture is documented using:

1. a **Complete System Architecture**,
2. a **Technical Wiring Diagram**,
3. an **EV3 Brick Wiring Diagram**,
4. a **Nano ↔ HuskyLens Wiring Diagram**,
5. and photographs of the physical implementation.

Together, these provide both the conceptual and physical information needed to understand and reproduce the current Cheese v4 wiring architecture.
