The wiring system is how every electronic part of Cheese is connected. The EV3 Brick works as the center of the system. Motors connect to output ports, LEGO sensors connect to input ports, and the Arduino Nano connects through USB so it can power and communicate with the HuskyLens camera.

This section includes both the previous wiring evidence and the current v4 wiring direction. The older v3 wiring is useful because it shows how Cheese handled lighting and camera support during earlier testing. The v4 wiring is the current goal because the robot became cleaner, lighter, and easier to inspect.

  <img src="https://img.shields.io/badge/Main_Hub-EV3_Brick-FFD43B?style=for-the-badge">

For a beginner, the wiring system can be understood like this:

<div align="center">

| Wiring Area | What It Connects | Why It Matters |
| :--- | :--- | :--- |
| **EV3 output ports** | EV3 Brick to motors | Sends power and control commands to drive and steering motors. |
| **EV3 input ports** | EV3 Brick to LEGO sensors | Powers and reads ultrasonic and color sensors. |
| **EV3 USB port** | EV3 Brick to Arduino Nano | Provides 5V power and connection for the Arduino Nano. |
| **Arduino Nano wiring** | Arduino Nano to HuskyLens | Powers the HuskyLens and allows I2C communication. |
| **Previous lighting wiring** | 9V battery to lamps | Supported visibility during earlier v3 testing. |
| **v4 cable routing** | Shorter and cleaner cable paths | Makes debugging and inspection easier. |

</div>

The most important idea is that wiring is not only about connecting parts. Wiring affects reliability. A loose, long, tangled, or unclear cable path can make debugging harder and can cause the robot to behave inconsistently.

<div align="center">

| **OUTPUT_D** | Empty | Not used in current layout | Unused |

Unused ports are still included because they make the wiring diagram easier to understand. If a port is empty, it should be labeled as unused instead of ignored.

## ❀ 2.2.3 Wiring Diagram Topology ────୨ৎ────────୨ৎ────

The wiring diagram shows the connection used in Cheese’s power and sensing architecture. The EV3 Brick with its rechargeable battery acts as the central control and power unit. It directly manages the drive motor, steering motor, ultrasonic sensors, and color sensor through its output and input ports.

The HuskyLens AI Camera is connected through an Arduino Nano, which works as an intermediate communication bridge between the vision system and the EV3-based control architecture. This layout keeps the main navigation sensors connected directly to the EV3 while separating the camera-processing system, making the wiring easier to understand, debug, and maintain during testing.

## ❀ 2.2.4 Arduino-HuskyLens Wiring Diagram ────୨ৎ────────୨ৎ────

The Arduino Nano and HuskyLens are connected using I2C wiring. The HuskyLens receives power through the Arduino Nano and sends vision data through the I2C signal wires.

<div align="center">

| HuskyLens Pin | Arduino Nano Pin | Function |
| :--- | :--- | :--- |
| **5V** | **5V** | Power supply for the HuskyLens. |
| **GND** | **GND** | Shared electrical ground. |
| **SDA** | **A4** | I2C data line. |
| **SCL** | **A5** | I2C clock line. |

</div>

The diagram below shows the I2C wiring connection between the HuskyLens AI Camera and the Arduino Nano. The HuskyLens receives power through the 5V and GND pins, while the SDA and SCL signal wires connect to the Arduino Nano’s A4 and A5 pins.

## ❀ 2.2.5 Power Flow vs. Data Flow ────୨ৎ────────୨ৎ────

The wiring system carries two different types of information: power and data.

<div align="center">

| Flow Type | What Moves Through the Wire | Example on Cheese |
| :--- | :--- | :--- |
| **Power flow** | Electrical energy used to run components. | EV3 battery powers motors, sensors, Arduino, and HuskyLens. |
| **Control flow** | Commands sent from the EV3 to components. | EV3 tells motors how fast or where to move. |
| **Sensor data flow** | Measurements sent back to the EV3. | Ultrasonic sensors and color sensor send readings. |
| **Vision data flow** | Camera information processed through Arduino/HuskyLens. | HuskyLens detects objects and sends information through the Arduino system. |

</div>

This distinction matters because a wiring problem can affect different systems in different ways. A power issue can make a component turn off or behave weakly. A data issue can make the component stay powered but send wrong or missing information.

## ❀ 2.2.6 Previous v3 Lighting Wiring ────୨ৎ────────୨ৎ────

In the previous v3 setup, Cheese used two auxiliary lamps powered by a separate 9V battery. These lamps were not powered directly by the EV3. This prevented the lighting system from taking energy from the EV3 rechargeable battery, which was needed for the motors, sensors, Arduino Nano, and HuskyLens system.

The two lamps were placed at different heights because they supported different sensing tasks. The upper lamp improved the HuskyLens camera’s view of the obstacle area, while the lower lamp illuminated the floor near the color sensor.

<div align="center">

| Lighting Component | Power Source | Position | Purpose | Status |
| :--- | :--- | :--- | :--- | :--- |
| **Upper helping lamp** | External 9V battery | Upper front area | Improved HuskyLens obstacle visibility | Previous v3 testing |
| **Lower helping lamp** | External 9V battery | Lower front area, near the floor | Improved color sensor floor illumination | Previous v3 testing |

</div>

## ❀ 2.2.9 Wiring Reproducibility Notes ────୨ৎ────────୨ৎ────

A wiring diagram is only useful if another person can follow it. For that reason, the wiring documentation should show:

<div align="center">

| Reproducibility Detail | Why It Matters |
| :--- | :--- |
| **Port labels** | Shows exactly where each component connects. |
| **Unused ports** | Prevents confusion about missing connections. |
| **Power vs. data flow** | Explains what each wire is doing. |
| **Arduino-HuskyLens pin table** | Makes the camera wiring reproducible. |
| **Legacy vs. current wiring** | Shows what changed without confusing old and new systems. |
| **Photos from multiple angles** | Helps verify physical cable routing. |

</div>

This is why v3 and v4 evidence are both included. The v3 wiring shows previous testing solutions, while the v4 layout shows the current cleaner design.

## ✦ Final Wiring Summary ─── ⋆⋅☆⋅⋆ ───

The v4 wiring layout became easier to understand and maintain because every active cable has a clear purpose: motor control, sensor reading, camera communication, or power delivery.

Cheese’s wiring is centered around the EV3 Brick. The motors connect to output ports, the LEGO sensors connect to input ports, and the Arduino Nano connects through USB. The HuskyLens connects to the Arduino Nano using power, ground, and I2C signal wires.

The previous v3 lighting system is included as engineering evidence because it helped solve detection problems during testing. The current v4 layout is cleaner because the camera was lowered, the mount was simplified, and cable routing became easier to inspect.

<p align="center">
  <strong>Final wiring lesson:</strong><br>
  Good wiring is not only about connecting parts. It is about making power, data, debugging, and reproducibility clear.
</p>
