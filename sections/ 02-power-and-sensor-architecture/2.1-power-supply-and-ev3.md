Cheese uses the **LEGO MINDSTORMS EV3 rechargeable battery** as its main energy source.

The EV3 Brick acts as both the main controller and the center of the robot's electrical architecture. It powers the LEGO motors and sensors while also providing the USB connection used by the Arduino Nano.

For the obstacle challenge, the Arduino Nano acts as the communication bridge between the EV3 and the HuskyLens vision system.

The current v4 architecture was also simplified compared with v3. The previous auxiliary lighting system and its additional structure were removed, reducing wiring and unnecessary hardware.

## ❀ 2.1.2 EV3 Rechargeable Battery ────୨ৎ────────୨ৎ────

The main power source of Cheese is the **LEGO MINDSTORMS EV3 rechargeable battery pack**.

The battery supplies the EV3 Brick, which then distributes electrical power to the connected LEGO motors and sensors.

We use **two EV3 rechargeable batteries in rotation** during testing. While one battery is being used, the other can be charged.

This became important because Cheese does not behave exactly the same when the battery becomes weak.

| Battery Aspect | Implementation |
| :--- | :--- |
| **Main source** | EV3 rechargeable battery |
| **Battery packs available** | 2 |
| **Testing strategy** | Rotate charged batteries |
| **Main powered controller** | EV3 Brick |
| **Reason for rotation** | Improve consistency between tests |

## ❀ 2.1.3 Power Distribution & Complete System Architecture ────୨ৎ────────୨ৎ────

Cheese uses a centralized architecture built around the EV3 Brick.

The battery first supplies the EV3. From there, electrical power and control are distributed to the different robot subsystems.

<p align="center">
  <strong>Battery → EV3 → Actuation / Sensing / Communication</strong>
</p>

These systems can be divided into three main branches:

| Branch | Components | Purpose |
| :--- | :--- | :--- |
| **Actuation** | Large Motor + Medium Motor | Movement and steering |
| **LEGO sensing** | Ultrasonic sensors + Color sensor | Track and distance information |
| **Vision communication** | USB + Arduino Nano + HuskyLens | Obstacle recognition |

## ❀ 2.1.6 HuskyLens ↔ Arduino Nano I2C Wiring ────୨ৎ────────୨ৎ────

The HuskyLens and Arduino Nano communicate through **I2C**.

The essential wiring is:

| HuskyLens | Arduino Nano | Function |
| :--- | :--- | :--- |
| **VCC** | **5V** | Power |
| **GND** | **GND** | Common electrical ground |
| **SDA** | **A4 / SDA** | I2C data |
| **SCL** | **A5 / SCL** | I2C clock |

The communication chain can therefore be represented as:

<p align="center">
  <strong>HuskyLens ⇄ I2C ⇄ Arduino Nano ⇄ USB ⇄ EV3</strong>
</p>

## ❀ 2.1.7 Power Consistency During Testing ────୨ৎ────────୨ৎ────

Power became an important testing variable during Cheese's development.

A robot can still turn on with a partially discharged battery while behaving differently from a run performed with a freshly charged battery.

The most noticeable effects occur in systems that depend on motor response.

| Battery Condition | Possible Effect |
| :--- | :--- |
| **Fresh / charged** | More consistent drive and steering response |
| **Partially discharged** | Response may begin to differ from previous tuning |
| **Weak battery** | Motor behavior can become less consistent |
| **Different battery conditions between tests** | Makes software and mechanical comparison harder |

This matters because a change in robot behavior does not automatically mean that the code is wrong.

For example:

<p align="center">
  <strong>
    Different curve behavior ≠ automatically a PID problem
  </strong>
</p>

Battery condition, mechanical friction, sensor conditions, and software tuning can all affect a run.

For this reason, battery condition is checked before making major tuning decisions.

---

## ❀ 2.1.8 Power Effects on Drive & Steering ────୨ৎ────────୨ৎ────

The drive and steering systems are particularly important because both rely on motors.

### Drive Motor

The EV3 Large Motor provides propulsion.

Changes in motor response can alter:

- straight-line speed,
- acceleration,
- time before reaching a curve,
- timing between sensor detection and physical movement.

### Steering Motor

The EV3 Medium Motor controls the front steering linkage.

Its response affects:

- how quickly a steering command becomes physical wheel movement,
- curve entry,
- wall avoidance,
- obstacle avoidance,
- recovery after corrections.

This is especially important because Cheese performs navigation while continuously moving.

The software may request the correct steering angle, but the mechanical system still needs enough time to physically execute that command.

## ❀ 2.1.9 Battery Rotation as an Engineering Control ────୨ৎ────────୨ৎ────

Using two rechargeable EV3 batteries is not only convenient.

It became part of our **testing methodology**.

Consider two runs:

| Run | Software | Mechanical Setup | Battery | Result |
| :--- | :---: | :---: | :---: | :--- |
| **A** | Same | Same | Charged | Stable |
| **B** | Same | Same | Weak | Different behavior |

Without considering battery condition, Run B could incorrectly lead us to change PID values, steering angles, or mechanical parts.

Therefore, we try to control the power variable before modifying another system.

<p align="center">
  <strong>
    Testing rule:<br>
    Keep power conditions as consistent as possible before comparing tuning changes.
  </strong>
</p>

This makes troubleshooting more systematic.

## ❀ 2.1.10 v3 Auxiliary Lighting → v4 Simplification ────୨ৎ────────୨ৎ────

Earlier versions of Cheese experimented with auxiliary lighting.

The purpose was to improve visual conditions around the HuskyLens and color-sensing system.

However, the additional system introduced:

- more wiring,
- additional structural pieces,
- another power source,
- additional weight,
- more components to troubleshoot.

During the v4 redesign, the camera position and upper structure were changed.

The permanent auxiliary lighting structure was therefore removed from the current robot.

A component can provide a benefit during experimentation without necessarily being worth keeping in the final design.

## ✦ 2.1 Engineering Lessons ─── ⋆⋅☆⋅⋆ ───

The development of Cheese showed us that electrical architecture cannot be separated from mechanical and software performance.

Three major lessons came from the power system:

### 1. Stable power is part of repeatable testing

Testing software with different battery conditions can produce misleading results.

### 2. Wiring must be documented physically and logically

A diagram explains the intended architecture, but photographs prove how that architecture was actually implemented.

### 3. More hardware is not automatically better

The previous auxiliary lighting system added functionality, but it also added wiring, structure, weight, and another power source. The v4 redesign allowed us to simplify this system.

The final Cheese v4 electrical architecture therefore focuses on:

<p align="center">
  <strong>
    stable power · accessible wiring · clear communication paths · reproducibility
  </strong>
</p>

---

## ✦ Final Power Supply Summary ─── ⋆⋅☆⋅⋆ ───

Cheese v4 is powered primarily by the EV3 rechargeable battery, with the EV3 Brick serving as the central control and LEGO power-distribution unit.

The EV3 controls the drive and steering motors, reads the LEGO sensors, and connects to the Arduino Nano through USB. For the obstacle challenge, the Arduino Nano communicates with the HuskyLens through I2C.

The v4 redesign also simplified the electrical architecture by removing the permanent auxiliary lighting system used during previous testing.

Most importantly, testing showed that battery condition can affect robot behavior. Because of this, power consistency is treated as a controlled engineering variable before changing PID values, steering parameters, sensor logic, or mechanical components.
