Calibration means checking that the sensors are reading the environment correctly before expecting the robot to drive well. A sensor can give different readings if its height, angle, lighting, distance, or movement changes.

For Cheese, calibration was not one single step. It was a repeated process based on testing, observing failures, changing values, and testing again. This was especially important because Cheese uses different types of sensors: ultrasonic sensors for walls, a color sensor for floor markers, and a HuskyLens camera for obstacles.

## ❀ 2.4.3 How the Color Sensor Was Tested ────୨ৎ────────୨ৎ────

The color sensor was tested directly on the real track. This mattered because the robot does not drive on a theoretical surface. It drives on the actual mat, under the actual lighting conditions, with the actual colored lines.

The color sensor did not create many problems compared with the ultrasonic sensors. However, using it as part of the navigation strategy was still an important decision. At first, it could seem easier to make the ultrasonic sensors do most of the work: detect walls, regulate the PID, and help the robot understand curves. But that would give the ultrasonic sensors too many responsibilities.

Instead, we used the color sensor to help with progress and curve counting. This reduced the amount of work that the ultrasonic sensors had to handle.

<div align="center">

| Color Sensor Test Focus | Why It Mattered |
| :--- | :--- |
| **Testing on real colored lines** | The sensor needed to recognize the actual colors on our mat. |
| **Checking repeated readings** | We needed to know if the same line produced similar results each time. |
| **Using it for curve / line counting** | It helped the robot know where it was in the run. |
| **Reducing ultrasonic workload** | The ultrasonic sensors could focus more on wall distance and PID correction. |

</div>

The color sensor became useful because it gave Cheese a different type of information from the ultrasonic sensors. The ultrasonic sensors answer “How close am I to the wall?” while the color sensor answers “What floor marker did I pass?”

---

## ❀ 2.4.4 Color Sensor Mode and Color Grouping ────୨ৎ────────୨ৎ────

The color sensor runs in **COL-COLOR mode**. In this mode, the EV3 color sensor classifies what it sees as a built-in color category instead of making the code interpret raw RGB values directly.

This was useful because it kept the program simpler. The sensor already knows how to classify colors, so our code can focus on what to do when a useful color is detected.

The difficult part was the orange line. The orange line was not always classified as one single color. Depending on lighting, sensor height, surface reflection, and movement, the sensor could read the orange line as different warm colors.

Instead of forcing the sensor to report only one exact value, the code treated several warm colors as the same useful marker.

<p align="center">
  <strong>Orange group = red + yellow + brown</strong>
</p>

<div align="center">

| Track Color | Possible Sensor Reading | Code Interpretation |
| :--- | :--- | :--- |
| **Orange line** | Red | Orange marker detected. |
| **Orange line** | Yellow | Orange marker detected. |
| **Orange line** | Brown | Orange marker detected. |
| **Blue line** | Blue | Blue marker detected. |

</div>

This approach worked because it matched how the sensor actually behaved on the real track. The goal was not to make the sensor perfect. The goal was to make the robot react reliably to the readings the sensor actually produced.

---

## ❀ 2.4.5 Why the Color Sensor Was Calibrated on the Real Track ────୨ৎ────────୨ৎ────

We did not choose the color behavior only from theory, a datasheet, or another team’s robot. We tested it on the real mat.

This matters because a color sensor reading depends on several physical conditions:

<div align="center">

| Condition | How It Can Affect the Reading |
| :--- | :--- |
| **Paint color** | The real orange or blue may not match a perfect digital color. |
| **Surface finish** | A shiny or matte surface reflects light differently. |
| **Ambient lighting** | Room light can slightly change what the sensor sees. |
| **Sensor height** | A higher or lower sensor can receive different reflected light. |
| **Robot movement** | Fast movement can make the sensor pass over a line quickly. |

</div>

Calibrating on the real surface made the color sensor more reliable because the code was based on what Cheese actually saw during testing.

<p align="center">
  <strong>Real track testing → real sensor behavior → better color decisions</strong>
</p>

---

## ❀ 2.4.6 How Ultrasonic Readings Were Checked ────୨ৎ────────୨ৎ────

The ultrasonic sensors were checked through repeated driving tests and distance-reading observations. Unlike the color sensor, they were not calibrated with a formal startup routine. Instead, we improved their behavior by testing how the robot reacted to the wall readings.

During testing, the ultrasonic sensors were used to support PID and wall following. When the robot drifted, overcorrected, or crashed, we checked whether the problem came from steering behavior, PID values, sensor readings, or physical placement.

<div align="center">

| Ultrasonic Testing Method | Purpose |
| :--- | :--- |
| **Repeated runs near walls** | Checked whether the robot could follow the wall consistently. |
| **Distance value observation** | Helped identify readings that looked too high, too low, or unstable. |
| **PID tuning** | Adjusted how strongly the robot reacted to wall-distance errors. |
| **Placement changes** | Helped improve the physical direction and height of the readings. |
| **v4 sensor lowering** | Improved alignment between the ultrasonic beam and the side walls. |

</div>

This process is slower than a single calibration button, but it reflects how we actually improved the robot: test, observe, adjust, and test again.

---

## ❀ 2.4.7 Ultrasonic Sensor Issues and Adjustments ────୨ৎ────────୨ৎ────

The ultrasonic sensors gave us more problems than the color sensor. This is because wall readings can change depending on height, angle, distance, movement, and the way the sound beam hits the wall.

<div align="center">

| Issue | Why It Happened | Adjustment / Response | Result |
| :--- | :--- | :--- | :--- |
| **Wall readings were inconsistent** | The sensor angle or height could affect the echo. | Repeated wall-distance tests and PID adjustments. | More controlled correction behavior. |
| **Robot corrected too late** | The sensor reading or tuning did not trigger correction early enough. | Adjusted distance thresholds and steering response values. | Better reaction near walls. |
| **Robot overcorrected** | PID or steering response was too aggressive. | Reduced or tuned correction strength. | Smoother movement after testing. |
| **Sensor beam could miss useful wall surface** | Sensors were too high or not aligned well enough with the wall. | Lowered ultrasonic sensors in v4. | Better physical alignment with the wall. |
| **Failures were sometimes diagnosed after a run** | No formal startup validation routine existed. | Used test results to adjust values and placement. | Identified need for better pre-run checks in the future. |

</div>

The main lesson from the ultrasonic sensors is that calibration is not only about the sensor. It also depends on the robot’s structure, the sensor height, the sensor angle, and the code that reacts to the readings.

## ❀ 2.4.9 Problems Caused by Shadows, Height, Angle, Distance, and Movement ────୨ৎ────────୨ৎ────

Sensor readings are affected by physical conditions. A sensor can be good, but still produce poor results if it is placed badly or tested under inconsistent conditions.

<div align="center">

| Condition | Sensor Most Affected | Possible Problem |
| :--- | :--- | :--- |
| **Shadows / lighting changes** | HuskyLens, color sensor | Objects or colors may look darker or less clear. |
| **Height** | Ultrasonic sensor, color sensor, HuskyLens | Sensor may look above the wall, too far from floor, or at the wrong obstacle area. |
| **Angle** | Ultrasonic sensor, HuskyLens | Signal or view may not point toward the correct target. |
| **Distance** | Ultrasonic sensor, HuskyLens | Target may be too close, too far, or not centered. |
| **Movement** | All sensors | Fast movement can reduce the time available to detect and react. |

</div>

This is why the v4 redesign matters for calibration. By making the robot lower, cleaner, and easier to inspect, it also made sensor testing easier. The sensors are not floating alone; they depend on the chassis and structure around them.

---

## ❀ 2.4.10 How v4 Changes May Improve Reliability ────୨ৎ────────୨ৎ────

The v4 redesign improved the conditions around the sensors. The robot became more stable, lighter, and cleaner, with a better center of gravity and less unnecessary structure. This can improve reliability because sensors and motors are held in more stable positions.

<div align="center">

| v4 Change | Why It Helps Calibration / Reliability |
| :--- | :--- |
| **Lower ultrasonic sensors** | Better alignment with the side walls. |
| **Simpler camera structure** | Easier camera inspection and less unnecessary upper mass. |
| **Shorter cables** | Less chance of cables blocking sensors or movement. |
| **Color sensor kept in working position** | Avoided unnecessary recalibration. |
| **Cleaner layout** | Easier to inspect sensors before testing. |
| **More stable motor placement** | Reduces structural movement that can affect sensor behavior. |
| **Lower center of gravity** | Helps make movement less chaotic during sensor-based corrections. |

</div>

The v4 redesign did not magically solve every sensor issue, but it made testing easier and reduced some physical sources of error.

---

## ❀ 2.4.11 Calibration Is Repeated, Not One Single Step ────୨ৎ────────୨ৎ────

Calibration is a slow process. For us, it takes many repeated tests, similar conditions, and small adjustments. It is difficult to find the exact point that works because Cheese uses more than one sensor, and each sensor behaves differently.

A single test is not enough because one good run can happen by luck. A better calibration process needs repeated evidence.

<p align="center">
  <strong>Test → observe → adjust → repeat → compare results</strong>
</p>

<div align="center">

| Calibration Step | What We Do |
| :--- | :--- |
| **Test** | Run the robot or sensor under real conditions. |
| **Observe** | Watch what fails or what readings look unstable. |
| **Adjust** | Change placement, thresholds, PID values, or code response. |
| **Repeat** | Run the same test again to see if the change helped. |
| **Compare** | Decide if the result is better, worse, or unchanged. |

</div>

This repeated process is important because sensor behavior changes with height, angle, lighting, distance, movement, battery level, and structure. Calibration is not just “setting a value.” It is finding values and placements that survive real testing.

The ultrasonic sensors improved through repeated wall-following tests. The HuskyLens still needs the same real-condition testing process.

---

## ✦ Final Sensor Calibration Summary ─── ⋆⋅☆⋅⋆ ───

Calibration was necessary because sensor readings can change depending on height, angle, lighting, distance, and movement.

The color sensor was tested on the real track and became reliable for floor marker detection and curve counting. The ultrasonic sensors were checked through repeated distance tests, wall-following behavior, and PID tuning, but they still need a stronger pre-run validation process. The HuskyLens calibration is still pending and will need to be trained using real obstacle pillars.

<p align="center">
  <strong>Final calibration lesson:</strong><br>
  A sensor is not reliable only because it is connected. It becomes reliable when its readings are tested, understood, repeated, and improved under real conditions.
</p>
