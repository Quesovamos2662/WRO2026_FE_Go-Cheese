## 5.2.1 Building Cheese v4

Cheese v4 was not created by simply adding components to the previous robot.

The robot was rebuilt around four priorities:

<div align="center">

| Priority | Design Objective |
| :---: | :--- |
| **Compact** | Remove unnecessary upper structure and unused supports |
| **Accessible** | Keep the EV3, battery, sensors and wiring inspectable |
| **Stable** | Maintain rigid steering, drivetrain and sensor geometry |
| **Testable** | Make individual subsystems easier to verify before full runs |

</div>

The previous v3 robot weighed approximately **888.8 g**.

The current Cheese v4 weighs approximately **666 g**.

That represents a reduction of approximately:

<p align="center">
  <strong>888.8 g → 666 g = 222.8 g removed</strong>
</p>

<p align="center">
  <strong>≈ 25% reduction in total robot mass</strong>
</p>

The result is a significantly simpler physical architecture while preserving the systems required for the WRO Future Engineers challenges.

# 5.2.4 System Layers

Cheese can be understood as a set of connected construction layers.

<div align="center">

| Layer | Main Elements | Function |
| :---: | :--- | :--- |
| **1 — Chassis** | Technic beams, pins, axles and supports | Structural foundation |
| **2 — Drive** | Large Motor, rear axle and rear wheels | Propulsion |
| **3 — Steering** | Medium Motor, Ackermann linkage and front wheels | Direction control |
| **4 — Control** | EV3 Brick and rechargeable battery | Main processing and power |
| **5 — Sensors** | 3 Ultrasonics + Color Sensor | Wall, front and floor sensing |
| **6 — Vision** | HuskyLens + Arduino Nano | Obstacle recognition and communication |

</div>

<p align="center">
  <strong>
    Structure → Motion → Control → Sensing → Vision
  </strong>
</p>

These systems should be assembled and tested progressively instead of installing everything before the first test.

# 5.2.5 Recommended Construction Sequence

<div align="center">

| Stage | Assembly Operation | Verification |
| :---: | :--- | :--- |
| **01** | Build lower chassis | Frame is rigid and straight |
| **02** | Install rear drivetrain | Axle rotates freely |
| **03** | Install Large Motor | Motor securely transfers drive |
| **04** | Assemble Ackermann steering | Linkage moves without binding |
| **05** | Install Medium Motor | Steering can center correctly |
| **06** | Install wheels | All wheels have correct clearance |
| **07** | Mount EV3 + battery | Controller is stable and accessible |
| **08** | Mount Ultrasonics | Sensors maintain intended orientation |
| **09** | Mount Color Sensor | Correct floor clearance |
| **10** | Mount HuskyLens + Nano | Vision direction remains stable |
| **11** | Connect wiring | Ports match software configuration |
| **12** | Secure cables | No interference with moving systems |
| **13** | Mechanical verification | Robot rolls and steers freely |
| **14** | Sensor verification | Sensors produce valid readings |
| **15** | Open calibration | Navigation and parking tested |
| **16** | Obstacle calibration | Detection, avoidance and recovery tested |

</div>

<p align="center">

# 5.2.6 Step 1 — Construct the Lower Chassis

The lower chassis is the reference structure for every other subsystem.

<p align="center">
  <img src="../../v-photos/v4/bottom_chassis_layout_v4.jpg"
       alt="Cheese v4 lower chassis"
       width="74%">
</p>

The current v4 chassis is intentionally simpler than the previous design.

The team removed unnecessary structural elements rather than adding reinforcement everywhere.

### Construction objectives

- maintain a rigid central structure,
- provide secure motor supports,
- maintain left/right alignment,
- leave space for the steering linkage,
- support the EV3 at a lower position,
- and avoid unnecessary mass.

### Before continuing

Check that:

- beams are not visibly twisted,
- pins are fully inserted,
- axles are not under sideways load,
- steering space remains clear,
- and the chassis sits naturally on a flat surface.

---

# 5.2.7 Step 2 — Rear Drive Assembly

The rear wheels provide propulsion.

<p align="center">
  <img src="../../v-photos/v4/rear_drive_wheels_v4.jpg"
       alt="Cheese v4 rear drive wheels"
       width="68%">
</p>

The rear axle should be installed so that both wheels rotate without rubbing nearby LEGO elements.

The assembly must remain mechanically aligned because unnecessary resistance changes how the robot responds to the same motor command.

### Manual check

Rotate the rear wheels before powering the robot.

They should rotate without:

- strong friction,
- axle binding,
- structural rubbing,
- or excessive side movement.

# 5.2.9 Step 4 — Ackermann Steering Assembly

The front steering system is one of the most mechanically sensitive assemblies on Cheese.

<p align="center">
  <img src="../../v-photos/v4/ackerman_steering_top_v4.jpg"
       alt="Cheese v4 Ackermann steering"
       width="76%">
</p>

The system uses a mechanical linkage so that the front wheels can follow different paths during a turn.

This is important because the wheel on the inside of a corner follows a smaller radius than the outside wheel.

### Assembly check

Move the mechanism manually through:

<p align="center">
  <strong>
    Full Left → Center → Full Right → Center
  </strong>
</p>

There should be:

- no binding,
- no beam contact,
- no cable contact,
- no wheel/chassis collision,
- and no excessive looseness.

<p align="center">
  <a href="../../schemes/steering_comparison_v3_to_v4.pdf">
    <strong>Open the Cheese v3 → v4 Steering Comparison</strong>
  </a>
</p>

# 5.2.10 Step 5 — Steering Motor

The EV3 Medium Motor controls the steering mechanism.

<p align="center">
  <img src="../../v-photos/v4/medium_motor_internal_v4.jpg"
       alt="Cheese Medium steering motor"
       width="62%">
</p>

### Electrical connection

<p align="center">
  <strong>Medium Motor → EV3 Output A</strong>
</p>

The motor should be mechanically secure because movement of the motor mount changes the effective steering angle.

### Establish physical center

Before autonomous testing:

1. place the steering approximately at its mechanical center,
2. verify both front wheels point approximately forward,
3. check available travel to the left,
4. check available travel to the right,
5. then establish the software steering reference.

A badly misaligned mechanical center should not be hidden with a large software correction.

# 5.2.11 Step 6 — Front Wheel Assemblies

The current front wheels are the distinctive light-blue wheel assemblies shown on the real robot.

<p align="center">
  <img src="../../v-photos/v4/front_spike_wheels_v4.jpg"
       alt="Cheese v4 front wheel assemblies"
       width="66%">
</p>

Only the **front wheel assemblies** were changed during the v4 redesign.

The rear drive wheels remain a different EV3/Technic-style wheel assembly.

This distinction is important when reproducing Cheese:

<p align="center">
  <strong>
    Front Wheels ≠ Rear Wheels
  </strong>
</p>

After installation, verify:

- both wheels rotate freely,
- both steering pivots move freely,
- the wheels clear the chassis,
- and both wheels maintain appropriate floor contact.

# 5.2.15 Step 10 — Color Sensor Installation

The EV3 Color Sensor is mounted underneath the robot facing the field.

<p align="center">
  <img src="../../v-photos/v4/color_sensor_front_layout_v4.jpg"
       alt="Cheese Color Sensor placement"
       width="59%">
</p>

### Connection

<p align="center">
  <strong>Color Sensor → EV3 Input 4</strong>
</p>

The sensor should be positioned close to the field without physically touching it.

<p align="center">
  <img src="../../v-photos/v4/color_sensor_floor_gap_v4.jpg"
       alt="Cheese Color Sensor floor clearance"
       width="59%">
</p>

The floor gap is especially important.

Too high can reduce reading consistency.

Too low can cause the sensor or its support to drag during motion.

An earlier light-blocking cover was removed after it created physical interference. The current v4 arrangement instead uses the improved sensor position and floor clearance.

# 5.2.21 Cable Routing

Once all devices are connected, route the cables around the mechanical systems.

<p align="center">
  <img src="../../v-photos/v4/wiring_overview_v4.jpg"
       alt="Cheese v4 wiring overview"
       width="75%">
</p>

Cheese does not require perfectly hidden wiring.

It requires **safe wiring**.

The important requirement is that cables do not interfere with:

- steering linkage,
- front wheel movement,
- rear wheels,
- drive axle,
- or sensor view.

<p align="center">
  <strong>
    Electrical Cable in Moving Mechanism = Mechanical Failure Risk
  </strong>
</p>

# 5.2.22 Mechanical Verification

Before autonomous testing, Cheese should pass a complete physical inspection.

<div align="center">

| Check | Expected Result |
| :--- | :--- |
| Roll Cheese manually | Smooth movement |
| Rotate rear wheels | No abnormal binding |
| Move steering left/right | Free linkage movement |
| Return steering to center | Wheels return near neutral |
| Inspect motor mounts | No movement |
| Inspect EV3 | Secure |
| Inspect side Ultrasonics | Stable orientation |
| Inspect front Ultrasonic | Clear forward view |
| Inspect Color Sensor | Does not contact floor |
| Inspect HuskyLens | Stable forward angle |
| Inspect cables | No mechanical interference |

</div>

If one of these tests fails, fix the physical system before modifying software.

---

# 5.2.23 Sensor Verification

After mechanical inspection, test the sensors individually.

### Ultrasonics

Move a flat object toward each sensor.

The measured distance should decrease consistently.

### Color Sensor

Move the sensor across:

- neutral floor,
- blue marking,
- orange / recognized curve marking.

Verify that the software distinguishes the expected events.

### HuskyLens

Present real obstacle pillars individually.

Confirm:

<p align="center">
  <strong>Green → ID 1</strong><br>
  <strong>Red → ID 2</strong>
</p>

Do not begin avoidance tuning until recognition itself is sufficiently repeatable.

---

# 5.2.24 Software Verification Order

A full run should not be the first software test.

Use progressively larger tests.

<p align="center">
  <strong>
    Component → Subsystem → Combined Behavior → Full Challenge
  </strong>
</p>

For example:

<div align="center">

| Test Level | Example |
| :---: | :--- |
| **Component** | Read one ultrasonic |
| **Subsystem** | Wall-following correction |
| **Combined** | Wall following + corner |
| **Full system** | Complete three-lap Open run |

</div>

This makes failures much easier to isolate.

---

# 5.2.25 Open Challenge Build Validation

After assembly, the Open Challenge should be validated in this order:

<p align="center">
  <strong>
    Straight → PID → Walls → Corners → Curve Count → Recovery → 3 Laps → Parking
  </strong>
</p>

### Straight

Verify basic propulsion and steering center.

### PID

Verify that small distance errors produce small corrections instead of large oscillations.

### Wall protection

Test progressively closer wall positions.

### Corners

Check both entry and exit trajectory.

### Curve counting

Confirm that one physical curve corresponds to one valid count.

### Recovery

Test front safety behavior separately.

### Full run

Only then attempt three complete laps.

### Parking

Parking should be tested after curve counting is sufficiently reliable because the finish depends on progress tracking.

# 5.2.27 Obstacle Challenge Build Validation

Obstacle calibration follows a different progression.

<p align="center">
  <strong>
    Detect → Identify → Choose Side → Avoid → Clear Pillar → Recover → Continue
  </strong>
</p>

Test one behavior at a time.

### 1. Detection

Can HuskyLens consistently see the pillar?

### 2. Identification

Is the correct ID returned?

### 3. Passing rule

- Green → left
- Red → right

### 4. Clearance

Does Cheese completely clear the obstacle?

### 5. Recovery

Does the robot return toward a useful trajectory after avoidance?

This final step is especially important because recovery after an obstacle remains one of the principal tuning challenges of the current system.

# 5.2.29 Failure Isolation Guide

When something goes wrong, first identify **which system failed**.

<div align="center">

| Observed Failure | Inspect First |
| :--- | :--- |
| Strong drift while driving | Wheel alignment / drivetrain |
| Steering remains turned | Steering linkage / Medium Motor |
| Constant zig-zag | Sensor readings / PID response |
| Incorrect wall correction | Ultrasonic position / port |
| Front recovery missing | Front Ultrasonic |
| Incorrect curve count | Color Sensor / validation logic |
| HuskyLens sees pillar but EV3 does not react | Nano / USB communication |
| Correct recognition but pillar is hit | Avoidance timing / strength |
| Pillar cleared but robot later hits wall | Post-obstacle recovery |
| Parking starts early or late | Curve count |
| Same code suddenly behaves weaker | Battery / mechanical resistance |

</div>

<p align="center">
  <strong>
    Failure → Isolate → Change One Variable → Retest
  </strong>
</p>

---

# 5.2.30 Construction Mistakes to Avoid

### Do not use software to compensate for severe mechanical problems

A crooked wheel is not a PID problem.

### Do not change sensor position casually

Sensor geometry is part of the calibration.

### Do not allow the Color Sensor to drag

The robot changes height slightly during motion and curves.

### Do not leave the HuskyLens loose

Camera movement changes obstacle geometry.

### Do not route cables through steering

The cable can physically restrict the mechanism.

### Do not rebuild removed v3 systems

Cheese v4 does **not** use the previous auxiliary-light system or its large supporting structure.

### Do not assume front and rear wheels are interchangeable

They are intentionally different assemblies.

# 5.2.32 Reproducibility Test

A reconstruction is not complete simply because it visually resembles Cheese.

It should pass four verification levels.

<div align="center">

| Level | Requirement |
| :---: | :--- |
| **1 — Mechanical** | Robot rolls and steers correctly |
| **2 — Electrical** | Motors and sensors are correctly connected |
| **3 — Sensing** | Distance, floor and vision data are valid |
| **4 — Autonomous** | Systems work together during navigation |

</div>

<p align="center">
  <strong>
    Similar Appearance ≠ Functional Reproduction
  </strong>
</p>

A reproducible Cheese must preserve the relationships between its systems.

---

# 5.2.35 Final Build Philosophy

Cheese v4 is not defined by one component.

Its behavior comes from the relationship between:

<p align="center">
  <strong>
    Chassis + Steering + Drive + Sensors + Vision + Wiring + Software
  </strong>
</p>

A mechanical change can alter a sensor reading.

A sensor change can alter a steering correction.

A steering change can alter a corner exit.

A corner exit can alter when the next obstacle enters the camera.

For that reason, reproducing Cheese means reproducing **the system**, not simply its appearance.

<p align="center">
  <strong>
    Correct Components<br>
    + Correct Geometry<br>
    + Correct Connections<br>
    + Correct Calibration<br>
    = Reproducible Cheese v4
  </strong>
</p>
