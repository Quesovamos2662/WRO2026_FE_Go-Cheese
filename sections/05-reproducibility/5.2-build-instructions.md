## 5.2.1 Scope of This Assembly Guide

Cheese v4 is a compact redesign of Cheese v3.

The current robot has a measured mass of approximately **666 g**, compared with
**888.8 g** for the previous v3 build.

The v4 redesign changed the physical arrangement of several systems:

- EV3 Brick placed flatter,
- Large Motor mounted horizontally,
- lower ultrasonic sensor placement,
- simplified HuskyLens support,
- front SPIKE wheel assemblies,
- shorter Nano USB cable,
- removal of the old auxiliary-light system,
- and removal of unnecessary upper structure.

The main build principle is:

<p align="center">
  <strong>
    Do Not Only Rebuild the Shape.<br>
    Rebuild the Function and Geometry of Each Subsystem.
  </strong>
</p>

A robot can contain the same components and still behave differently if:

- an ultrasonic sensor is tilted,
- the Color Sensor is too high,
- the HuskyLens angle changes,
- the steering linkage is not centered,
- one wheel has excessive friction,
- or a cable interferes with a moving mechanism.

## 5.2.3 Recommended Build Order

Cheese should be assembled from the mechanical foundation upward.

Do not install every component immediately.

The recommended sequence is:

<p align="center">
  <strong>
    Chassis → Drive → Steering → Wheels → EV3 → Ultrasonics → Color Sensor → HuskyLens → Nano → Wiring → Verification → Calibration
  </strong>
</p>

<div align="center">

| Stage | Assembly Step | Verify Before Continuing |
| :---: | :--- | :--- |
| **1** | Lower chassis | Structure is straight and rigid |
| **2** | Rear drivetrain | Wheels rotate freely |
| **3** | Large Motor | Drive axle moves without binding |
| **4** | Front steering linkage | Mechanism moves symmetrically |
| **5** | Medium Motor | Steering center can be established |
| **6** | Front and rear wheels | All wheels touch correctly |
| **7** | EV3 Brick and battery | Controller is stable and accessible |
| **8** | Side ultrasonics | Both face their walls correctly |
| **9** | Front ultrasonic | Forward sensing is unobstructed |
| **10** | Color Sensor | Correct floor clearance |
| **11** | HuskyLens | Forward view is clear |
| **12** | Arduino Nano | Safe placement and communication |
| **13** | Wiring | No cable interferes with movement |
| **14** | Mechanical verification | Robot rolls and steers correctly |
| **15** | Sensor verification | Values respond correctly |
| **16** | Software calibration | Open and Obstacle testing |

</div>

# 5.2.4 Step 1 — Build the Lower Chassis

Start with the lower structural frame.

<p align="center">
  <img src="../../v-photos/v4/bottom_chassis_layout_v4.jpg"
       alt="Cheese v4 lower chassis"
       width="76%">
</p>

The chassis supports:

- rear drivetrain,
- steering assembly,
- EV3 Brick,
- motors,
- sensors,
- and upper electronic components.

The goal is not maximum part count.

The goal is sufficient rigidity with minimum unnecessary structure.

### Chassis requirements

<div align="center">

| Requirement | Reason |
| :--- | :--- |
| **Straight structure** | Prevents mechanical drift |
| **Rigid motor supports** | Motors should not move under load |
| **Free steering region** | Linkages must not touch chassis parts |
| **Parallel wheel supports** | Helps maintain predictable motion |
| **Low unnecessary mass** | Reduces inertia |
| **Accessible electronics area** | Simplifies repairs and testing |

</div>

### Check before continuing

Place the unfinished chassis on a flat surface.

Confirm that:

- no beam is visibly twisted,
- no axle is being forced sideways,
- left and right chassis rails are aligned,
- and no structural pin is under unnecessary stress.

# 5.2.5 Step 2 — Install the Rear Drivetrain

The rear system provides propulsion.

<p align="center">
  <img src="../../v-photos/v4/rear_drive_wheels_v4.jpg"
       alt="Cheese v4 rear drivetrain"
       width="66%">
</p>

Install the rear axle and wheel-support structure before finalizing the electronics.

The rear drivetrain should:

- rotate smoothly,
- remain aligned,
- avoid side-to-side axle movement,
- and transfer motor motion without excessive friction.

### Manual drivetrain test

Before connecting the Large Motor electrically:

1. Rotate the rear wheels by hand.
2. Check that both sides move without rubbing the chassis.
3. Verify that bushings or spacers hold the axle in position.
4. Confirm that no cable or structural element touches the rotating system.

<p align="center">
  <strong>
    Mechanical Resistance Should Be Fixed Mechanically Before Software Testing.
  </strong>
</p>

# 5.2.7 Step 4 — Assemble the Ackermann Steering

The front steering mechanism is one of the most sensitive mechanical systems in Cheese.

<p align="center">
  <img src="../../v-photos/v4/ackerman_steering_top_v4.jpg"
       alt="Cheese v4 Ackermann steering system"
       width="72%">
</p>

The assembly includes:

- steering axle,
- steering linkage,
- front-wheel supports,
- Technic pins,
- bushings,
- axles,
- and the Medium Motor connection.

The steering should move without binding.

### Important

Do not force both front wheels to remain exactly parallel through the entire turn.

The current system uses Ackermann-style steering geometry.

The inner and outer wheels therefore follow slightly different steering angles during a turn.

### Manual test

Before installing or powering the steering motor:

1. Move the linkage gently by hand.
2. Turn fully left.
3. Return to center.
4. Turn fully right.
5. Check that no axle binds.
6. Check that no wheel touches the chassis.

The mechanism should return smoothly.

# 5.2.8 Step 5 — Install the Medium Steering Motor

The Medium Motor controls the steering system.

<p align="center">
  <img src="../../v-photos/v4/medium_motor_internal_v4.jpg"
       alt="Cheese v4 Medium steering motor"
       width="62%">
</p>

### Connection

**Medium Motor → EV3 Output A**

Its mechanical function is:

<p align="center">
  <strong>
    Medium Motor → Steering Linkage → Front Wheel Angle
  </strong>
</p>

The motor must be mounted securely because even small movement in the motor support can change the wheel angle.

### Steering center

Before autonomous testing, establish the physical steering center.

At center:

- both front wheels should point approximately forward,
- the linkage should not already be near one mechanical limit,
- and equal steering authority should remain available in both directions.

Do not use software offsets to hide a severely misaligned physical steering mechanism.

- front wheels,

- drive axle,

### Good cable routing

A cable should:

- have enough slack for normal movement,
- not be pulled tightly,

<p align="center">

# 5.2.23 Mechanical Verification Before Power-On

Before starting autonomous software, perform a complete mechanical inspection.

<div align="center">

| Test | Expected Result |
| :--- | :--- |
| Roll robot manually | Wheels move without abnormal resistance |
| Rotate rear wheels | Drivetrain rotates smoothly |
| Turn steering manually | Linkage does not bind |
| Check steering extremes | Wheels do not touch chassis |
| Push lightly on EV3 | Brick does not shift |
| Push lightly on motors | Motor mounts remain rigid |
| Check side sensors | Sensors do not move |
| Check camera | Angle remains fixed |
| Inspect Color Sensor | No floor contact |
| Inspect cables | Nothing enters moving mechanisms |

</div>

Do not begin software tuning until these tests pass.

---

# 5.2.24 Steering Verification

Power the EV3 and test only the Medium Motor.

Check:

1. steering center,
2. small left movement,
3. return to center,
4. small right movement,
5. return to center,
6. larger left/right movement.

The wheels should follow the commands without sticking.

### Failure examples

If Cheese remains turned after returning to zero:

- inspect linkage friction,
- inspect motor mount,
- inspect axle binding,
- and verify steering calibration.

If left and right response are physically different, solve the mechanical asymmetry before tuning navigation.

---

# 5.2.25 Drive Verification

Test the Large Motor at low speed before full-speed operation.

The robot should move forward without:

- wheel skipping,
- rear axle binding,
- chassis vibration,
- or major mechanical pull to one side.

A small natural deviation can later be handled by navigation control.

A severe deviation should be corrected mechanically first.

---

# 5.2.26 Ultrasonic Verification

Test each sensor separately.

### Test method

Place Cheese next to a flat wall.

Move it gradually closer and farther.

The measured distance should respond in the expected direction.

<div align="center">

| Sensor | Verification |
| :--- | :--- |
| **Left** | Left distance decreases when left wall gets closer |
| **Right** | Right distance decreases when right wall gets closer |
| **Front** | Front distance decreases when object moves closer |

</div>

If a value behaves incorrectly:

1. inspect the port,
2. inspect cable connection,
3. inspect physical angle,
4. inspect whether the sensor is blocked,
5. then inspect software.

---

# 5.2.27 Color Sensor Verification

Before Open Challenge testing:

1. place Cheese over neutral field surface,
2. record the sensor behavior,
3. move the sensor across blue,
4. move it across orange / recognized curve color,
5. confirm the software interprets the expected event.

The Color Sensor should not repeatedly count the same physical line as multiple curves.

The current software uses event validation rather than assuming:

<p align="center">
  <strong>
    One Reading = One Curve
  </strong>
</p>

The correct philosophy is:

<p align="center">
  <strong>
    Color Reading → Sequence Validation → Steering Confirmation → Valid Curve
  </strong>
</p>

---

# 5.2.28 HuskyLens Verification

Obstacle recognition should be tested separately from robot movement.

Use real competition-colored pillars.

Confirm:

<div align="center">

| Test Object | Expected Recognition |
| :--- | :---: |
| **Green pillar** | ID 1 |
| **Red pillar** | ID 2 |

</div>

Do not immediately tune avoidance if recognition itself is unstable.

First verify:

- detection distance,
- viewing angle,
- pillar position in frame,
- and lighting conditions.

Only after detection is sufficiently repeatable should steering behavior be tuned.

---

# 5.2.29 EV3 ↔ Nano Communication Verification

Before testing obstacle movement, verify that the EV3 actually receives camera information.

The expected chain is:

<p align="center">
  <strong>
    Pillar → HuskyLens → Nano → USB → EV3
  </strong>
</p>

If HuskyLens recognizes a pillar but Cheese does not react:

### Check in this order

1. HuskyLens detection
2. I²C connection
3. Nano processing
4. USB connection
5. EV3 serial parsing
6. obstacle-control logic

This prevents changing steering code when the real failure is communication.

---

# 5.2.30 Open Challenge Calibration Sequence

Once the build passes individual tests, begin Open Challenge calibration.

The recommended order is:

<p align="center">
  <strong>
    Straight Driving → Wall Correction → Cornering → Curve Counting → Front Recovery → Three Laps → Parking
  </strong>
</p>

Do not tune every Open behavior simultaneously.

### Stage A — Straight driving

Test whether Cheese can move through a straight section without excessive oscillation.

### Stage B — Wall correction

Tune corrections so they are strong enough to protect Cheese without producing constant zig-zag.

### Stage C — Corners

Verify entry, steering angle and exit heading.

### Stage D — Curve counting

Confirm that one physical curve produces one valid event.

### Stage E — Front recovery

Test the safety behavior separately with a controlled close-wall situation.

### Stage F — Full run

Only after the previous behaviors work individually should Cheese attempt the complete three-lap sequence.

### Stage G — Parking

Parking should be tuned last because its activation depends on correct progress through the earlier run.

---

# 5.2.31 Obstacle Challenge Calibration Sequence

Obstacle testing should begin only after the mechanical and sensor architecture is stable.

Recommended order:

<p align="center">
  <strong>
    Recognition → Single-Pillar Pass → Clearance → Recovery → Repeated Pillars → Corners + Pillars → Parking
  </strong>
</p>

### Stage 1 — Recognition

Verify Green ID 1 and Red ID 2.

### Stage 2 — Single pillar

Test one obstacle in a controlled straight section.

### Stage 3 — Passing side

Verify:

- Green → left
- Red → right

### Stage 4 — Clearance

Confirm Cheese fully passes the pillar without contacting or carrying it.

### Stage 5 — Recovery

After passing, Cheese must return toward a useful navigation trajectory.

### Stage 6 — Consecutive obstacles

Only then test sequences where a second pillar appears after the first.

### Stage 7 — Obstacle parking

Parking should remain one of the last systems to finalize because avoidance changes the robot's final position.

---

# 5.2.32 Failure Isolation During Testing

If Cheese crashes, do not immediately change several constants.

Identify the subsystem first.

<div align="center">

| Failure | First System to Inspect |
| :--- | :--- |
| Robot pulls strongly on straight | Wheels / chassis / drivetrain |
| Steering stays turned | Steering mechanism / steering motor |
| Wrong wall correction | Ultrasonic geometry / port assignment |
| Front recovery never activates | Front ultrasonic / threshold |
| Curve count incorrect | Color Sensor / event logic |
| Pillar visible but no reaction | Camera → Nano → EV3 communication |
| Pillar recognized but hit anyway | Avoidance timing / steering strength |
| Correct avoidance then later crash | Recovery |
| Parking activates early | Curve-count logic |
| Same code suddenly weaker | Battery / mechanical resistance |

</div>

The troubleshooting principle is:

<p align="center">
  <strong>
    Observe → Isolate → Change One Variable → Retest
  </strong>
</p>

---

# 5.2.33 Build Problems to Avoid

### Do not overtighten the structure

Technic pieces should be secure but should not be forced into misalignment.

### Do not allow axle side-load

An axle that is forced sideways creates friction.

### Do not hide bad steering center with software

Correct the physical linkage first.

### Do not allow cables inside the steering region

A cable can physically limit steering.

### Do not move sensors casually

Changing sensor height or angle changes calibration.

### Do not change camera angle without retesting

Vision geometry directly affects obstacle timing.

### Do not test with a weak battery and immediately rewrite constants

Verify power condition first.

# 5.2.36 Reproducibility Acceptance Test

A Cheese v4 reconstruction should not be considered complete simply because it looks similar.

The rebuilt robot should pass four levels of verification.

<div align="center">

| Level | Test | Requirement |
| :---: | :--- | :--- |
| **1** | Mechanical | Wheels, drivetrain and steering move correctly |
| **2** | Electrical | Motors and sensors communicate through correct ports |
| **3** | Sensor | Ultrasonic, color and vision readings respond correctly |
| **4** | System | Robot performs controlled autonomous navigation |

</div>

Only after these four levels are passed should performance tuning begin.

---

# 5.2.37 Build Architecture Summary

The completed Cheese v4 can be viewed as five connected layers.

<div align="center">

| Layer | Components |
| :--- | :--- |
| **Mechanical** | Chassis, wheels, axles, Ackermann steering |
| **Motion** | Large Motor + Medium Motor |
| **Control** | EV3 Brick + rechargeable battery |
| **Sensing** | 3 Ultrasonics + Color Sensor |
| **Vision / Communication** | HuskyLens + Arduino Nano + USB |

</div>

These layers depend on one another.

For example:

<p align="center">
  <strong>
    Loose Sensor → Bad Measurement → Bad Correction → Bad Trajectory
  </strong>
</p>

and:

<p align="center">
  <strong>
    Bad Steering Geometry → Bad Corner → Bad Exit → Wall Risk
  </strong>
</p>

This is why the assembly guide includes verification instead of only mechanical instructions.

# 5.2.39 Final Assembly Summary

Cheese v4 should be built and tested as a connected engineering system.

The recommended workflow is:

<p align="center">
  <strong>
    Build Mechanical Base → Verify Movement → Install Electronics → Verify Sensors → Connect Vision → Verify Communication → Calibrate → Full Run
  </strong>
</p>

The most important lesson for reproduction is:

<p align="center">
  <strong>
    A Robot That Looks Like Cheese Is Not Automatically a Reproduction of Cheese.
  </strong>
</p>

A functional reproduction must also preserve:

- steering geometry,
- wheel roles,
- sensor placement,
- sensor height,
- camera angle,
- port assignment,
- communication architecture,
- cable clearance,
- and calibration.

<p align="center">
  <strong>
    Correct Parts + Correct Assembly + Correct Geometry + Correct Verification
    = Reproducible Cheese v4
  </strong>
</p>
