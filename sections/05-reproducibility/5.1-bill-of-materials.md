# ❀ 5.1.5 Ackermann Steering Components ────୨ৎ────────୨ৎ────

Cheese uses front-wheel Ackermann-style steering rather than differential steering.

<p align="center">
  <img src="../../v-photos/v4/ackerman_steering_top_v4.jpg"
       alt="Cheese v4 Ackermann steering mechanism"
       width="72%">
</p>

The steering assembly includes:

- Medium Motor,
- steering axle,
- Technic linkages,
- wheel supports,
- front axles,
- bushings/spacers,
- and the two front wheel assemblies.

The geometry is critical.

Even if another builder owns all the same components, changing the linkage geometry can change the physical turning radius.

Therefore:

<p align="center">
  <strong>
    Same Components + Different Steering Geometry ≠ Same Robot Behavior
  </strong>
</p>

# ❀ 5.1.10 Vision Communication Bridge — Arduino Nano ────୨ৎ────────୨ৎ────

The Arduino Nano is not the main controller of Cheese.

It acts as the bridge between the HuskyLens vision system and the EV3 architecture.

<p align="center">
  <img src="../../v-photos/v4/arduino_nano_position_v4.jpg"
       alt="Arduino Nano position on Cheese v4"
       width="60%">
</p>

The communication architecture is:

<p align="center">
  <strong>
    HuskyLens → I²C → Arduino Nano → USB Serial → EV3
  </strong>
</p>

The four HuskyLens I²C conductors are:

<div align="center">

| HuskyLens Connection | Arduino Nano |
| :--- | :--- |
| **VCC** | 5V |
| **GND** | GND |
| **SDA / T** | A4 / SDA |
| **SCL / R** | A5 / SCL |

</div>

The Nano then communicates with the EV3 through USB.

<p align="center">
  <img src="../../v-photos/v4/ev3_usb_to_nano_v4.jpg"
       alt="EV3 USB to Arduino Nano connection on Cheese v4"

Exact minor reinforcement counts can change slightly as the robot is maintained.

The current approximate inventory is:

<div align="center">

| Structural Component | Approx. Qty. | Function | Reproducibility Priority |
| :--- | :---: | :--- | :---: |

</div>

The important reproducibility distinction is:

<p align="center">
  <strong>
    Exact Color Is Flexible.<br>
    Geometry Is Not.
  </strong>
</p>

Moving an ultrasonic sensor several centimeters is not equivalent.

# ❀ 5.1.16 v3 → v4 Component Transition ────୨ৎ────────୨ৎ────

Cheese v4 is not a completely unrelated robot.

Many major systems were carried over and repositioned.

<div align="center">

| ୨ৎ Carried Over | ୨ৎ Modified / Repositioned | ୨ৎ Removed |
| :--- | :--- | :--- |
| EV3 Brick | EV3 orientation | Large camera structure |
| EV3 rechargeable battery | Large Motor orientation | Auxiliary light system |
| EV3 Large Motor | HuskyLens position | Lamp mounts |
| EV3 Medium Motor | Ultrasonic positions | External lighting battery/support |
| EV3 Color Sensor | Color-sensor floor gap | Lighting wiring |
| Ultrasonic Sensors | Front wheel system | Upper tower structure |
| HuskyLens | Nano USB cable | Extra liftarms |
| Arduino Nano | Cable organization | Extra pins |
| Rear drive wheels | Overall chassis architecture | Extra axles/supports |
| Useful Technic pieces | Ackermann integration | Unnecessary reinforcement |

</div>

The engineering strategy was:

<p align="center">
  <strong>
    Reuse Proven Systems → Modify Limiting Systems → Remove Unnecessary Systems
  </strong>
</p>

# ❀ 5.1.19 Software-Dependent BOM Components ────୨ৎ────────୨ৎ────

Some BOM elements are directly referenced by software.

This means they cannot be moved or replaced casually.

<div align="center">

| Hardware | Software Dependency |
| :--- | :--- |
| **Large Motor** | Drive commands |
| **Medium Motor** | Steering commands |
| **Left Ultrasonic** | Wall-distance controller |
| **Right Ultrasonic** | Wall-distance controller |
| **Front Ultrasonic** | Safety / reverse recovery |
| **Color Sensor** | Floor-color and curve events |
| **HuskyLens** | Pillar color / position information |
| **Arduino Nano** | Vision-data bridge |

</div>

Therefore:

<p align="center">
  <strong>
    Hardware Change → Possible Software Change → Recalibration
  </strong>
</p>

This is why the BOM includes function and geometry rather than only component names.

# ❀ 5.1.20 Replacement Rules ────୨ৎ────────୨ৎ────

If another builder needs to substitute a component, the following rules should be considered.

<div align="center">

| Replacement | Usually Safe? | Requirement |
| :--- | :---: | :--- |
| **Same liftarm in another color** | ✅ | Same geometry |
| **Equivalent pin color** | ✅ | Same mechanical connection |
| **Different cable retention method** | ✅ | No interference with moving parts |
| **Different minor reinforcement** | ⚠️ | Must preserve rigidity |
| **Different Nano mounting method** | ⚠️ | Must preserve safe wiring |
| **Different ultrasonic position** | ❌ | Requires recalibration |
| **Different color-sensor height** | ❌ | Requires recalibration |
| **Different wheel diameter** | ❌ | Changes physical behavior |
| **Different steering linkage** | ❌ | Changes turning geometry |
| **Different motor type** | ❌ | Changes control response |
| **Different camera position** | ❌ | Changes detection geometry |

</div>

# ❀ 5.1.21 Rebuild Priority Order ────୨ৎ────────୨ৎ────

    ↓<br>
    2. Steering + Wheels<br>
    ↓<br>
    3. EV3 + Battery<br>
    ↓<br>
    4. Ultrasonic + Color Sensors<br>
    ↓<br>
    5. HuskyLens + Arduino Nano<br>
    ↓<br>
    6. Wiring<br>
    ↓<br>
    7. Calibration
  </strong>
</p>

This prevents a builder from calibrating sensors before the mechanical geometry is stable.

<p align="center">
