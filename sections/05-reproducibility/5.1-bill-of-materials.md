A Bill of Materials is more than a list of parts. For Cheese, the BOM also explains which components are critical, which parts can vary slightly, which elements were carried over from v3, and which parts were removed during the transition to v4.

The current version of Cheese is **v4**, a more compact and lighter redesign. The v3 robot weighed approximately **888.8 g**, documented as **888 g** for calculations. The current v4 robot weighs approximately **666 g**, and we do not expect small future adjustments to change this value drastically.

The main engineering idea behind the v4 BOM is:

<p align="center">
  <strong>Keep the parts that are necessary, modify the parts that affect performance, and remove the parts that add weight or complexity without enough benefit.</strong>
</p>

## ❀ 5.1.1 Purpose of This Bill of Materials ────୨ৎ────────୨ৎ────

This section supports reproducibility. Another person should be able to understand what Cheese v4 uses, what each component does, and which components are important for the robot’s behavior.

This BOM also documents the version transition from v3 to v4. This is important because the robot did not change randomly. The v4 component list was shaped by testing, failures, calibration problems, and design decisions.

<div align="center">

| Purpose | Explanation |
| :--- | :--- |
| **Current build documentation** | Lists the main components used in Cheese v4. |
| **Reproducibility** | Helps another builder understand what is needed to recreate the robot. |
| **Version tracking** | Shows what changed from v3 to v4. |
| **Engineering reasoning** | Explains why some parts were kept, modified, or removed. |
| **Maintenance** | Makes it easier to inspect, repair, and update the robot during testing. |

</div>

## ❀ 5.1.3 Current v4 Port and Connection Map ────୨ৎ────────୨ৎ────

The following table documents the current connection layout used by Cheese v4.

<div align="center">

| Component | Port / Connection | Purpose |
| :--- | :---: | :--- |
| **EV3 Large Motor** | Output B | Drives the rear wheels and moves the robot forward. |
| **EV3 Medium Motor** | Output A | Controls the steering mechanism. |
| **Left Ultrasonic Sensor** | Input 1 | Reads the left wall distance. |
| **Right Ultrasonic Sensor** | Input 2 | Reads the right wall distance. |
| **Front Ultrasonic Sensor** | Input 3 | Reads front distance and helps detect close obstacles or walls. |
| **Color Sensor** | Input 4 | Detects floor colors for line and curve counting. |
| **Arduino Nano** | EV3 USB port | Supports communication between the EV3 system and the HuskyLens. |
| **HuskyLens** | Connected to Arduino Nano | Detects red and green obstacles for the Obstacle Challenge. |

</div>

This port map is important because the code depends on the same physical connections. If a sensor is connected to a different input without updating the program, the robot may read the wrong data and behave incorrectly.

## ❀ 5.1.4 Main Electronic and Control Components ────୨ৎ────────୨ৎ────

<div align="center">

| Component | Quantity | Current v4 Status | Main Function | Notes |
| :--- | :---: | :---: | :--- | :--- |
| **LEGO EV3 Brick** | 1 | Current | Main controller | Runs the navigation code and controls EV3 motors and sensors. |
| **EV3 Rechargeable Battery** | 1 | Current | Main power source | Powers the EV3 system, motors, and EV3-connected sensors. |
| **Arduino Nano ATmega328P** | 1 | Current, not final mounted | Vision communication bridge | Connected through the EV3 USB port and used with the HuskyLens. |

The EV3 Brick is the main controller because it directly supports LEGO motors and sensors. The Arduino Nano is not the main controller of the robot. Its role is to support the HuskyLens connection and help integrate the camera system into the EV3-based architecture.

In the current v4 build, the Arduino Nano is not mounted in a final fixed bracket yet. It is positioned on or near the robot during testing. This is documented honestly because the camera and Nano layout is still being optimized.

## ❀ 5.1.5 Motors and Movement Components ────୨ৎ────────୨ৎ────

<div align="center">

| Component | Quantity | Current v4 Status | Main Function | Notes |
| :--- | :---: | :---: | :--- | :--- |
| **EV3 Large Motor** | 1 | Current | Propulsion / drive motor | Mounted horizontally in v4 and connected to Output B. |
| **EV3 Medium Motor** | 1 | Current | Steering control | Connected to Output A and used to turn the front steering system. |
| **Rear Drive Wheels** | 2 | Current | Main driving wheels | Rear wheels remain EV3 / Technic style wheels. |
| **Front SPIKE Wheel Assemblies** | 2 | Current v4 update | Steering and front contact | Added in v4 for better grip, turning behavior, and steering support. |
| **Rear drive axle / connection** | 1 system | Current | Transfers motion to rear wheels | Keeps rear wheels aligned with the drive system. |
| **Ackermann steering linkage** | 1 system | Current | Turns the front wheels | Connects steering motor behavior to the front wheel angle. |

</div>

The wheel setup is important because Cheese uses a rear-drive and front-steering layout. The rear wheels provide propulsion, while the front wheels guide the robot’s direction.

In v4, only the **front wheels** were changed to SPIKE blue wheel assemblies. The rear wheels stayed the same. This matters because the SPIKE front wheels help the robot during steering, turning, and curve behavior, while the rear wheels still belong to the drive system.

<div align="center">

| Component | Quantity | Port / Connection | Current v4 Function | Notes |
| :--- | :---: | :---: | :--- | :--- |
| **Left Ultrasonic Sensor** | 1 | Input 1 | Reads left wall distance | Helps with wall following and correction. |
| **Right Ultrasonic Sensor** | 1 | Input 2 | Reads right wall distance | Helps with wall following and correction. |
| **Front Ultrasonic Sensor** | 1 | Input 3 | Reads front distance | Helps detect front walls or close-distance situations. |
| **Color Sensor** | 1 | Input 4 | Reads floor colors | Used for line and curve counting. |
| **HuskyLens AI Camera** | 1 | Arduino Nano | Detects obstacles | Red pillar = ID 1, green pillar = ID 2. |
| **Arduino Nano** | 1 | EV3 USB + HuskyLens wiring | Vision bridge | Supports camera communication with the EV3 system. |

</div>

The v4 robot uses **three ultrasonic sensors**: left, right, and front. The side ultrasonic sensors support wall-distance information, while the front ultrasonic sensor helps the robot detect distance in front of it.

The color sensor stayed in its working floor-facing placement because moving it would create unnecessary recalibration risk. The color sensor is important because line and curve counting are major parts of the Open Challenge logic.

The HuskyLens is mounted above the front sensor area and its angle is still being tested. The goal is to find the best angle for seeing obstacles clearly without wasting the camera’s view on areas that do not help obstacle detection.

## ❀ 5.1.8 LEGO Technic Structural Components ────୨ৎ────────୨ৎ────

The following quantities are approximate counts based on the current v4 build. Small LEGO Technic pieces can vary slightly depending on reinforcement and exact mounting choices.

<div align="center">

| **Technic liftarms / beams** | ~50 | Main frame, sides, motor support, sensor support | Quantity may vary slightly depending on reinforcement. |
| **Technic pins** | ~70 | Connects liftarms, beams, and support pieces | Some support pins can vary, but structural pins must keep the robot rigid. |

The v4 structure is a compact layout. The EV3 Brick is placed flatter with the screen facing upward, and the EV3 Large Motor is mounted horizontally. This reduced height and helped make the robot more practical to inspect and tune.

The goal of the v4 structure is not to use the smallest possible number of pieces. The goal is to use only the pieces that serve a clear function.

## ❀ 5.1.10 Components Modified from v3 to v4 ────୨ৎ────────୨ৎ────

Some components stayed in the robot but were modified in position, support, or configuration.

<div align="center">

| Component / System | v3 Situation | v4 Modification | Reason |
| :--- | :--- | :--- | :--- |
| **EV3 Brick** | Part of a taller and heavier layout. | Placed flatter with screen facing upward. | Improves access and supports a compact structure. |
| **EV3 Large Motor** | Previous orientation required more support structure. | Mounted horizontally. | Reduces height and improves integration into the chassis. |
| **HuskyLens camera** | Held by a larger camera structure. | Lowered and placed above the front sensor area. | Improves compactness while testing the best obstacle angle. |
| **Ultrasonic sensors** | Higher / less ideal placement. | Lowered in v4. | Helps use wall readings more effectively. |
| **Front wheels** | Previous front wheel setup. | Changed to SPIKE blue wheel assemblies. | Improves front grip and turning behavior. |
| **Nano USB cable** | Longer cable around the front/camera area. | Changed to shorter USB Type-A to Mini-B cable. | Reduces clutter near the Nano and camera. |
| **Cable routing** | More visually crowded because of old structure. | Reorganized through the compact layout. | Easier inspection and less interference risk. |

</div>

This table shows that v4 was not built from completely new parts. It was a redesign that reused many components in a more practical way.

## ❀ 5.1.13 Critical Components for Rebuilding Cheese v4 ────୨ৎ────────୨ৎ────

Some components are critical because changing them would affect the robot’s behavior, calibration, or code.

<div align="center">

| Critical Component | Why It Should Not Be Changed Without Recalibration |
| :--- | :--- |
| **EV3 Brick** | Main controller and connection base for EV3 motors and sensors. |
| **EV3 Large Motor** | Controls the drive system and affects speed/torque behavior. |
| **EV3 Medium Motor** | Controls steering response and turning behavior. |
| **Three Ultrasonic Sensors** | Sensor count and placement affect wall and front-distance logic. |
| **Color Sensor** | Used for floor detection and curve/line counting. |
| **HuskyLens** | Needed for red and green obstacle recognition. |
| **Arduino Nano** | Supports HuskyLens communication with the EV3 setup. |
| **Front SPIKE wheels** | Affect steering grip and curve response. |
| **Rear drive wheels** | Affect drive behavior and possible distance calculations. |
| **Steering linkage** | Directly affects how steering commands become wheel angles. |
| **Sensor positions** | Changing height or angle can change the readings. |
| **Motor ports and sensor ports** | The code expects components in specific ports. |

</div>

If any of these components are changed, the robot may still work, but it would need new testing and calibration.

## ❀ 5.1.14 Flexible or Substitute Components ────୨ৎ────────୨ৎ────

Some components can vary slightly without completely changing the robot’s function.

<div align="center">

| Flexible Component | What Can Vary | What Should Stay Consistent |
| :--- | :--- | :--- |
| **Color of liftarms** | Color can change. | Shape, length, and structural role should stay similar. |
| **Some support pins** | Pin color or type can vary if compatible. | Critical connections must stay tight and aligned. |
| **Minor support pieces** | Small reinforcement choices can vary. | Sensor and motor positions should not shift. |
| **Cable ties / wire fasteners** | Type and placement can vary. | Cables must stay away from wheels and steering. |
| **Non-critical bracing** | Small supports can change. | The chassis must remain rigid. |
| **Nano temporary support** | Can be improved with a cleaner mount later. | Nano must stay safely connected and avoid moving parts. |

</div>

This distinction helps another builder understand what must match exactly and what can be adapted based on available LEGO parts.
