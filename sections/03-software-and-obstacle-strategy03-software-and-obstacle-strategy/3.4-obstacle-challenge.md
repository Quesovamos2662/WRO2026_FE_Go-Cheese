The Obstacle Challenge is more complex than the Open Challenge because Cheese must continue navigating the field while also reacting to colored pillars.

Detecting a pillar is only the beginning.

A successful obstacle maneuver requires:

```text
SEE PILLAR
    ↓
IDENTIFY COLOR
    ↓
DETECT EARLY ENOUGH
    ↓
CHOOSE CORRECT PASSING SIDE
    ↓
STEER AROUND PILLAR
    ↓
CLEAR PILLAR
    ↓
RECOVER TRAJECTORY
    ↓
PREPARE FOR NEXT EVENT
```

The current obstacle system already connects camera detection to physical steering.

The largest remaining challenge is making this complete sequence **repeatable**.

# ❀ 3.4.2 Obstacle Challenge Objective ────୨ৎ────────୨ৎ────

Cheese must still navigate the course normally while reacting to pillars.

<div align="center">

| Objective | Meaning |
| :--- | :--- |
| **Maintain navigation** | Continue using wall sensors and steering control |
| **Detect pillars** | HuskyLens identifies red and green |
| **Receive usable vision data** | Nano sends simplified data to EV3 |
| **Choose correct side** | Red and green require different passing paths |
| **Avoid without contact** | Cheese must clear the obstacle rather than push it |
| **Recover** | Robot should return to stable navigation afterward |
| **Prepare for next obstacle** | Recovery should place the next pillar back inside useful FOV |
| **Finish round** | Parking will be adapted once avoidance is stable |

</div>

The main engineering difficulty is not simply classification.

It is coordinating:

```text
VISION
  +
WALL SAFETY
  +
STEERING
  +
SPEED
  +
RECOVERY
```

without letting those systems fight each other.

# ❀ 3.4.5 Obstacle System Architecture ────୨ৎ────────୨ৎ────

The obstacle system is divided into three layers.

<div align="center">

| Layer | Components | Main Role |
| :--- | :--- | :--- |
| **Navigation** | EV3, motors, ultrasonics, color sensor | Keep Cheese moving safely |
| **Vision** | HuskyLens + Arduino Nano | Detect and transmit pillar information |
| **Reaction** | EV3 steering + speed control | Convert camera information into avoidance |

</div>

The architecture is:

```text
ENVIRONMENT
    ↓
HUSKYLENS
    ↓
ARDUINO NANO
    ↓
EV3
    ↓
NAVIGATION + CAMERA LOGIC
    ↓
STEERING + DRIVE
    ↓
ROBOT MOVEMENT
```

The camera therefore does not drive Cheese independently.

It provides information that becomes one part of the final movement decision.

# ❀ 3.4.7 Pillar Identification Rules ────୨ৎ────────୨ৎ────

The HuskyLens uses fixed trained IDs.

<div align="center">

| Pillar | HuskyLens ID | Required Behavior |
| :--- | :---: | :--- |
| 🔴 **Red** | **ID 1** | Pass on the **right** |
| 🟢 **Green** | **ID 2** | Pass on the **left** |

</div>

The current challenge is not deciding which color is which.

The more difficult problem is converting a correct detection into a successful physical path around the obstacle.

# ❀ 3.4.8 HuskyLens → Nano Communication ────୨ৎ────────୨ৎ────

The HuskyLens communicates with the Arduino Nano using I²C.

```text
HuskyLens        Arduino Nano
VCC / 5V   →     5V
GND        →     GND
SDA        →     A4
SCL        →     A5
```

The high-level path is:

```text
HUSKYLENS
    │
   I²C
    │
    ▼
ARDUINO NANO
```

