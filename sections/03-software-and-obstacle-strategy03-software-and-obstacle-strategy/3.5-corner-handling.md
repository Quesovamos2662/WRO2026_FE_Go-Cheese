# ❀ 3.5.1 Corner Handling Objective ────୨ৎ────────୨ৎ────

A successful corner requires more than simply turning the steering motor.

```text
APPROACH
   ↓
DETECT / CONFIRM
   ↓
STEER
   ↓
PROTECT FROM WALLS
   ↓
EXIT
   ↓
STABILIZE
```

The same mechanical steering system is used in both rounds, but the conditions around the corner are different.

- **Open Challenge:** the color sensor helps confirm course progress.
- **Obstacle Challenge:** the corner also changes the HuskyLens viewing direction and the position of the next pillar inside the camera's field of view.

# ❀ 3.5.3 Mechanical Steering ────୨ৎ────────୨ৎ────

Cheese v4 uses Ackermann-style front steering.

<p align="center">
  <img src="../../v-photos/v4/ackerman_steering_top_v4.jpg"
       alt="Cheese v4 Ackermann steering"
       width="68%">
</p>

The software controls the Medium Motor, which changes the front wheel angle and therefore the curve followed by Cheese.

```text
STEERING COMMAND
      ↓
MEDIUM MOTOR
      ↓
FRONT WHEELS
      ↓
ROBOT CURVE
```

Because of this, mechanical geometry and software tuning must work together.

The current logic recognizes two main course states:

```text
BLUE
```

and

```text
ORANGE
```

A valid sequence can be:

```text
BLUE → ORANGE
```

or:

```text
ORANGE → BLUE
```

The program combines the color transition with steering confirmation and timing before increasing the curve counter.

# ❀ 3.5.5 Open Curve Counting ────୨ৎ────────୨ৎ────

The Open round contains:

```text
4 CORNERS × 3 LAPS = 12 CURVES
```

Important current parameters include:

<div align="center">

| Parameter | Value |
| :--- | :---: |
| **Total curves** | `12` |
| **Color-change window** | `3.0 s` |
| **Curve cooldown** | `1.5 s` |
| **Post-color steering window** | `0.9 s` |

</div>

The cooldown prevents one physical corner from being counted twice.

It affects the **counter only**; Cheese continues moving normally.

# ❀ 3.5.6 Steering and Wall Protection ────୨ৎ────────୨ৎ────

During a corner, Cheese continues using its minimum-correction PID and ultrasonic wall protection.

<p align="center">
  <img src="../../img/software-flowcharts%20v4/03_v4_minimum_correction_pid_controller.png"
       alt="Cheese v4 minimum correction PID"
       width="78%">
</p>

The controller attempts to use only the steering correction that is necessary.

```text
SAFE
 ↓
NORMAL PID

CLOSER TO WALL
 ↓
GENTLE CORRECTION

TOO CLOSE
 ↓
SEVERE WALL PROTECTION
```

Current important wall regions are:

<div align="center">

| Condition | Distance |
| :--- | :---: |
| **Gentle wall region** | `28 cm` |
| **Severe wall region** | `22 cm` |
| **Full wall avoidance** | `15 cm` |

</div>

This allows the robot to react to the real geometry of each corner instead of depending only on a fixed turn.

---

# ❀ 3.5.7 Front Safety and Recovery ────୨ৎ────────୨ৎ────

The front ultrasonic does **not** count curves.

Its main role is safety.

<p align="center">
  <img src="../../v-photos/v4/sensor_placement_front_v4.jpg"
       alt="Cheese v4 front ultrasonic placement"
       width="62%">
</p>

If Cheese approaches a wall too closely:

```text
FRONT WALL TOO CLOSE
      ↓
CONFIRM CONDITION
      ↓
REVERSE
      ↓
CREATE SPACE
      ↓
RESUME NAVIGATION
```

This gives Cheese an additional recovery layer when a corner is entered or exited incorrectly.

---

# ❀ 3.5.8 Post-Corner Stabilization ────୨ৎ────────୨ৎ────

The current Open architecture does not depend on a fixed recovery maneuver after every curve.

Instead:

```text
CORNER FINISHES
      ↓
STEERING REDUCES
      ↓
PID + WALL PROTECTION
      ↓
ROBOT STABILIZES
      ↓
NORMAL NAVIGATION
```

This allows the actual sensor readings to determine how much correction is needed after each corner.

# ❀ 3.5.10 Obstacle Challenge Corner Handling ────୨ৎ────────୨ৎ────

# ❀ 3.5.11 Obstacle Corner Sequence ────୨ৎ────────୨ৎ────

The desired Obstacle corner sequence is:

```text
APPROACH CORNER
      ↓
TURN
      ↓
KEEP WALL SAFETY
      ↓
CAMERA ROTATES WITH ROBOT
      ↓
EXIT CORNER
      ↓
STABILIZE
      ↓
CAMERA FACES USEFUL TRACK AREA
      ↓
PREPARE FOR NEXT PILLAR
```

A good Obstacle corner is not finished just because Cheese completed the turn.

It should also leave the robot in a useful position for the next obstacle.

---

# ❀ 3.5.12 Corner Geometry and Camera Visibility ────୨ৎ────────୨ৎ────

A poor corner exit can create a problem several moments later.

```text
BAD CORNER EXIT
      ↓
BAD ROBOT HEADING
      ↓
BAD CAMERA HEADING
      ↓
NEXT PILLAR ENTERS FOV LATE
      ↓
LESS REACTION DISTANCE
      ↓
LATE AVOIDANCE
```

This is important because an obstacle failure may actually begin during the previous corner.

During rotation, a pillar can also temporarily disappear from the camera:

```text
PILLAR VISIBLE
      ↓
CHEESE TURNS
      ↓
CAMERA ROTATES
      ↓
PILLAR LEAVES FOV
      ↓
CORNER CONTINUES
      ↓
PILLAR MAY REAPPEAR
```

For this reason, corner recovery and camera visibility are strongly connected.

# ❀ 3.5.14 Open vs Obstacle Corner Handling ────୨ৎ────────୨ৎ────

<div align="center">

| Open Challenge | Obstacle Challenge |
| :--- | :--- |
| Color sensor confirms progress | Camera visibility becomes important |
| Ultrasonics provide wall safety | Ultrasonics still provide wall safety |
| Main goal: clean curve + correct count | Main goal: clean curve + useful camera heading |
| Recovery prepares for normal PID | Recovery prepares for next pillar |
| Camera not required | HuskyLens orientation is important |

</div>

The same physical steering system is therefore used for two different control situations.

# ❀ 3.5.15 Main Corner Failure Modes ────୨ৎ────────୨ৎ────

<div align="center">

| Failure | Likely Cause | Improvement |
| :--- | :--- | :--- |
| **Curve too wide** | Steering too weak or late | Earlier / stronger controlled steering |
| **Curve too sharp** | Excessive steering | Reduce turn strength |
| **Double count** | Same marker detected twice | Validation + cooldown |
| **Missed count** | Color transition missed | Improve sensing / timing |
| **Bad exit angle** | Steering releases poorly | PID stabilization |
| **Wall contact** | Poor curve geometry | Wall protection |
| **Next pillar appears late** | Poor obstacle corner exit | Improve camera heading |
| **Obstacle transition unstable** | Vision and navigation conflict | Balance camera influence with safety |

</div>

One of the most important system-level failure chains is:

```text
BAD CORNER EXIT
      ↓
BAD CAMERA HEADING
      ↓
LATE PILLAR DETECTION
      ↓
LATE AVOIDANCE
```

# ❀ 3.5.16 Engineering Development ────୨ৎ────────୨ৎ────

Corner tuning follows an iterative process:

```text
TEST
 ↓
OBSERVE
 ↓
IDENTIFY FAILURE
 ↓
ADJUST
 ↓
TEST AGAIN
```

<div align="center">

| Failure | Cause | Change | Desired Result |
| :--- | :--- | :--- | :--- |
| Wide corner | Weak steering | Increase controlled turn | Smaller radius |
| Sharp corner | Excessive steering | Reduce turn strength | Better clearance |
| Double count | Repeated marker detection | Add validation / cooldown | One count per curve |
| Zig-zag after corner | Excessive correction | Minimum-correction PID | Stable exit |
| Wall approach | Poor geometry | Progressive wall protection | Safer curve |
| Late pillar after corner | Poor camera heading | Improve obstacle exit | Earlier detection |

</div>

This failure → cause → change → result process helps identify the real source of a problem instead of changing random values.

# ✦ Engineering Lessons ─── ⋆⋅☆⋅⋆ ───

### 1. A corner is more than a turn

The robot must enter, rotate, exit, and recover.

### 2. The color sensor confirms progress

The ultrasonics and steering system still control the physical geometry of the Open corner.

### 3. One physical corner should create one logical count

Color validation and cooldown help prevent duplicate counts.

### 4. Recovery is part of the corner

The maneuver is not complete until Cheese returns to a useful trajectory.

### 5. Obstacle corners are also camera movements

When Cheese rotates, the HuskyLens rotates with it.

### 6. A pillar failure may begin during the previous corner

A poor exit can make the next obstacle enter the camera's field of view too late.

### 7. Real video evidence is important

The GIFs show the complete behavior from entry to turn, exit, and recovery instead of only one static moment.

# ✦ 3.5 Corner Handling Summary ─── ⋆⋅☆⋅⋆ ───

Cheese v4 combines:

- Ackermann steering,
- side ultrasonic sensing,
- front-wall safety,
- color-based Open progress,
- curve-count validation,
- minimum-correction PID,
- progressive wall protection,
- sensor-driven stabilization,
- and HuskyLens camera geometry during Obstacles.

For the **Open Challenge**:

```text
CORNER
   ↓
VALID CURVE COUNT
   ↓
STABLE PID NAVIGATION
```

For the **Obstacle Challenge**:

```text
CORNER
   ↓
STABLE NAVIGATION
   ↓
USEFUL CAMERA HEADING
   ↓
NEXT PILLAR READY
```

The two real demonstrations provide physical evidence for both situations:

```text
curve_demonstration_v4.gif
        ↓
OPEN CORNER HANDLING
```

```text
obstacle_corner_handling_v4.gif
        ↓
OBSTACLE CORNER HANDLING
```

The central engineering idea is:

```text
GOOD CORNER
     ≠
ROBOT SIMPLY TURNED
```

Instead:

```text
GOOD CORNER
     =
SAFE ENTRY
     +
CONTROLLED TURN
     +
WALL CLEARANCE
     +
STABLE EXIT
     +
USEFUL NEXT POSITION
```

<p align="center">
  <strong>
    Approach → Turn → Protect → Exit → Stabilize → Prepare
  </strong>
</p>
