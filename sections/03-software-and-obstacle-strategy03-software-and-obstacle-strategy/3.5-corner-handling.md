<p align="center">
  <em>This section explains how Cheese v4 detects, confirms, counts, and exits corners. Corner handling is one of the most important parts of the robot because it connects floor color detection, steering behavior, curve counting, obstacle preparation, and final parking accuracy.</em>
</p>

<p align="center">
  ✦ ─── ⋆⋅☆⋅⋆ ─── 🧀🤖 ─── ⋆⋅☆⋅⋆ ─── ✦
</p>

Corner handling is not treated as a simple “see color and turn” behavior. In Cheese v4, a corner is treated as a **sequence**: the robot detects a first floor color, waits for the opposite color, checks that steering actually happened, counts one curve, resets the temporary curve state, and then returns to navigation.

This matters because the curve counter is not only used for movement. It also tells Cheese when the three-lap run is complete and when parking mode should activate.

---

## ❀ 3.5.1 Corner Handling Objective ────୨ৎ────────୨ৎ────

The objective of corner handling is to make Cheese turn at the correct moment, count the curve correctly, and exit the curve in a position that allows the robot to continue safely.

<div align="center">

| Objective | Why It Matters |
| :--- | :--- |
| **Detect floor colors reliably** | The color sensor tells the robot when a curve sequence is happening. |
| **Avoid false curve counts** | Wrong counts can make parking activate too early or too late. |
| **Turn with enough authority** | The robot must curve enough to stay near the center and prepare for the next section. |
| **Avoid opening the curve too much** | Wide curves make recovery harder, especially before obstacles. |
| **Recover after the curve** | The robot must return to stable navigation after the turn. |
| **Support obstacle preparation** | In Obstacle Challenge, the robot needs to be centered enough after a curve to see and avoid the next pillar. |

</div>

The current corner handling is **functional but still in calibration**. Cheese can complete curves well most of the time, but the team is still improving how tightly it turns and how well it becomes straight again after curving and avoiding obstacles.

---

## ❀ 3.5.2 Current Corner Handling Status ────୨ৎ────────୨ৎ────

<div align="center">

| Area | Current Status |
| :--- | :--- |
| **Open Challenge curves** | Mostly stable; Cheese completes them well when battery and sensors are consistent. |
| **Obstacle Challenge curves** | More difficult because Cheese must curve, detect a pillar, avoid it, and recover. |
| **Most common corner issue** | The robot sometimes turns too late or too wide. |
| **Main desired improvement** | Tighter curves so Cheese stabilizes closer to the center. |
| **Wall risk** | The exterior wall is more dangerous after curves because poor exit angle makes recovery harder. |
| **Curve count** | Usually reliable, but missed counts can still affect parking. |
| **Final status** | Close to final for Open, still being tuned for obstacle interaction. |

</div>

A good curve for Cheese is not just a curve that avoids the wall. A good curve should help the robot **cut the curve**, move toward the center, and align well enough to continue toward the next obstacle or straight section.

## ❀ 3.5.4 Color Sensor Role in Corners ────୨ৎ────────୨ৎ────

The color sensor is the main trigger for corner handling. It points toward the floor and reads the colored markings that appear during the curve sequence.

The sensor is not used like a continuous line follower. Instead, it works as an **event detector**.

<div align="center">

| Color Sensor Job | Meaning |
| :--- | :--- |
| **Detect first color** | Starts a possible curve sequence. |
| **Detect opposite color** | Confirms that the sequence progressed. |
| **Support curve count** | Allows the robot to track completed curves. |
| **Support parking timing** | Parking depends on reaching the required curve count. |
| **Reject irrelevant colors** | Prevents non-curve readings from affecting the counter. |

</div>

In the current setup, the color sensor is structurally in the same general position as before, but it is slightly lower. This helps Cheese read both floor colors more reliably. Earlier, sunlight made detection harder, especially for blue in some directions, but the lower sensor position has reduced the need for external light blocking during normal operation.

---

## ❀ 3.5.5 Color Reading Interpretation ────୨ৎ────────୨ৎ────

Cheese v4 uses the EV3 color sensor in `COL-COLOR` mode.

<div align="center">

| Sensor Reading | Code Meaning | Why |
| :--- | :--- | :--- |
| **Blue** | `BLUE` | Used as one side of the corner sequence. |
| **Red** | `ORANGE` | Helps detect the orange marker when the sensor classifies it differently. |
| **Yellow** | `ORANGE` | Helps detect orange under different lighting conditions. |
| **Brown** | `ORANGE` | Helps detect darker orange-like readings. |
| **Other / none** | ignored | Prevents unrelated readings from triggering corner logic. |

</div>

This interpretation makes the color system more flexible. Instead of depending on one perfect orange reading, Cheese accepts several EV3 color classifications as part of the orange marker group.

---

## ❀ 3.5.6 Two-Color Curve Rule ────୨ৎ────────୨ৎ────

A curve is considered valid when Cheese detects two opposite colors in the correct sequence.

<div align="center">

| Valid Sequence | Result |
| :---: | :--- |
| **BLUE → ORANGE** | Counts one completed curve. |
| **ORANGE → BLUE** | Counts one completed curve. |

</div>

This means Cheese does not count a curve immediately after seeing only one marker. The first color starts the sequence, and the opposite color completes it.

<div align="center">

| Stage | Robot Interpretation |
| :---: | :--- |
| **First color detected** | Possible curve started. |
| **Same color repeated** | Ignore; not a completed curve. |
| **Opposite color detected** | Possible curve completed. |
| **Steering confirmed** | Register one valid curve. |
| **Curve registered** | Increase `completed_curves` by one. |

</div>

This rule prevents repeated readings of the same marker from becoming fake curves.

---

## ❀ 3.5.7 Curve Counter Constants ────୨ৎ────────୨ৎ────

The curve counter uses timing and state variables to reduce false counting.

<div align="center">

| Constant / Variable | Value / Role | Purpose |
| :--- | :---: | :--- |
| `TOTAL_CURVES` | `12` | Full three-lap target. |
| `COLOR_CHANGE_WINDOW` | `3.0 s` | Opposite colors must appear close enough in time. |
| `CURVE_COOLDOWN` | `1.5 s` | Prevents double counting after a curve. |
| `POST_COLOR_STEERING_WINDOW` | `0.9 s` | Allows steering confirmation shortly after the second color. |
| `CORNER_TURN_MIN_TIME` | `0.03 s` | Confirms that steering was not just a tiny accidental movement. |
| `first_curve_color` | stored color | Remembers the first color in the sequence. |
| `pending_second_color` | stored second color | Waits for steering confirmation if needed. |
| `completed_curves` | progress count | Determines when the run is complete. |

</div>

These constants make the system safer because the robot must see the correct color sequence within the allowed time window and avoid counting the same curve twice.

---

## ❀ 3.5.8 Steering Confirmation ────୨ৎ────────୨ৎ────

Steering confirmation was added because the robot could sometimes see color without actually being in a real curve movement. If color alone controlled the counter, Cheese could count a curve from a false or poorly timed reading.

The steering confirmation checks whether the robot has actually commanded a steering movement during or shortly after the color sequence.

<div align="center">

| Without Steering Confirmation | With Steering Confirmation |
| :--- | :--- |
| A color flash could accidentally count. | The robot must also show curve-related steering. |
| The counter could increase even if the robot was not turning. | The counter is connected to real motion. |
| Parking could activate at the wrong time. | Parking depends on more trustworthy curve counts. |

</div>

This makes the curve counter more connected to the robot’s physical behavior, not just the color sensor reading.

---

## ❀ 3.5.9 Cooldown Protection ────୨ৎ────────୨ৎ────

Cooldown exists to prevent one curve from being counted more than once. This is important because the robot may stay near a color marker for more than one loop cycle.

<div align="center">

| Problem | Cooldown Response |
| :--- | :--- |
| Sensor sees the same curve marker for several loop cycles. | The code waits before allowing another curve count. |
| Robot moves slowly over a color area. | The same event does not create multiple counts. |
| Color reading flickers near the edge of a marker. | The counter does not instantly accept another curve. |

</div>

This is especially important because the loop runs very quickly. Without cooldown, one physical event could appear as many repeated software readings.

---

## ❀ 3.5.10 Physical Corner Movement ────୨ৎ────────୨ৎ────

A good Cheese v4 curve should be controlled and slightly inward. The team wants the robot to make tighter curves because wide curves can leave Cheese too far from the center and make it harder to recover before the next obstacle.

<div align="center">

| Corner Behavior | Current Observation |
| :--- | :--- |
| **Good curve** | Cheese cuts the curve and begins moving back toward the center. |
| **Best result** | The robot exits with enough stability to continue toward the next obstacle. |
| **Current improvement** | Curves are more closed than before. |
| **Remaining issue** | Some curves are still too wide or too late. |
| **Obstacle interaction** | After a curve and obstacle avoidance, getting straight again is still difficult. |

</div>

The team’s current goal is not to make the robot turn as sharply as possible. The goal is to make the curve **closed enough** to stay centered, but not so aggressive that the robot loses control or hits the wall.

---

## ❀ 3.5.11 Exterior Wall Risk ────୨ৎ────────୨ৎ────

The most dangerous wall during corner handling is usually the exterior wall, especially after a wide curve or after obstacle avoidance.

<div align="center">

| Wall Area | Risk Level | Explanation |
| :--- | :---: | :--- |
| **Interior wall** | Lower risk | Cheese usually does not hit the inner wall during current curves. |
| **Exterior wall** | Higher risk | Wide curve exit can push Cheese outward and make recovery harder. |
| **Both walls** | Medium risk | In some situations, the risk depends on direction and starting position. |

</div>

This is why tighter curve behavior matters. A curve that is too open may look safe at first, but it can create a bad exit angle that causes the robot to struggle later.

---

## ❀ 3.5.12 Front Ultrasonic Support ────୨ৎ────────୨ৎ────

The front ultrasonic sensor supports corner safety and recovery. It is especially useful when Cheese approaches a front wall or edge situation where continuing forward would be dangerous.

<div align="center">

| Front Ultrasonic Use | Purpose |
| :--- | :--- |
| **Detect front danger** | Helps prevent the robot from driving into the front wall. |
| **Trigger reverse recovery** | Allows Cheese to create space when too close. |
| **Support edge awareness** | Helps the robot respond when the track geometry changes near a corner. |
| **Assist safe movement** | Works together with side sensors and steering logic. |

</div>

The front ultrasonic does not replace the color sensor for curve counting. The color sensor tracks curve progress, while the front ultrasonic helps protect the robot physically.

---

## ❀ 3.5.13 Recovery After Curves ────୨ৎ────────୨ৎ────

In the current Open logic, Cheese mainly recovers after curves using PID and wall protection rather than a completely separate post-curve routine.

<div align="center">

| Recovery Method | Current Role |
| :--- | :--- |
| **PID correction** | Helps Cheese return to stable wall-guided movement. |
| **Side ultrasonic readings** | Show whether the robot is drifting toward a wall. |
| **Front ultrasonic safety** | Protects the robot if the front wall becomes too close. |
| **Steering return behavior** | Helps the steering move back toward a safer angle. |
| **Speed reduction near danger** | Gives the robot more time to recover. |

</div>

This recovery is one of the most important parts still being tuned. Cheese can turn well, but after a curve and obstacle avoidance, it still needs to become straighter so the camera can see the next pillar and the robot can avoid it correctly.

---

## ❀ 3.5.14 Connection Between Corner Handling and Obstacles ────୨ৎ────────୨ৎ────

Corner handling and obstacle avoidance are connected. The robot cannot treat them as completely separate problems.

<div align="center">

| Corner Result | Effect on Obstacle Challenge |
| :--- | :--- |
| **Centered exit** | Camera has a better view of the next obstacle. |
| **Wide exit** | Robot may approach the next obstacle from a bad angle. |
| **Late turn** | Robot may have less time to recover before the pillar. |
| **Poor recovery** | Obstacle avoidance may begin while the robot is still misaligned. |
| **Good curve count** | Parking and progress logic remain accurate. |

</div>

This is why the team is working on making the curves more closed. A tighter, more centered curve exit gives Cheese more time and space to detect the next obstacle.

---

## ❀ 3.5.15 Connection Between Corner Handling and Parking ────୨ৎ────────୨ৎ────

The curve counter directly affects parking. Cheese activates parking after the required number of curves has been counted.

<div align="center">

| Curve Count Result | Parking Effect |
| :--- | :--- |
| **Correct count** | Parking activates at the intended time. |
| **Missed curve** | Parking may activate late or fail to activate correctly. |
| **Double count** | Parking could activate early. |
| **Bad curve exit** | Robot may reach the finish area at an angle. |

</div>

The current target is:

<p align="center">
  <strong>TOTAL_CURVES = 12</strong>
</p>

This represents the three-lap Open Challenge target. Because parking depends on this count, corner handling is directly connected to final stop accuracy.

---

## ❀ 3.5.16 Development History ────୨ৎ────────୨ৎ────

Corner handling improved through multiple testing stages. Earlier in development, Cheese had problems with turning, color detection, and obstacle interaction.

<div align="center">

| Earlier Problem | What Happened | Improvement Direction |
| :--- | :--- | :--- |
| **Robot did not turn correctly** | At the beginning, Cheese sometimes continued forward or reacted too late. | Steering and PID behavior were adjusted. |
| **Obstacle was detected but not avoided** | The robot could see the obstacle but still carry it. | Avoidance strength and detection timing were improved. |
| **Color sensor affected by sunlight** | The sensor detected orange too easily and had trouble with blue in some directions. | Sensor height and physical setup were improved. |
| **Curve count affected parking** | Missed curve counts caused strange parking behavior. | Two-color pairing, cooldown, and steering confirmation were used. |
| **Wide curve exit** | Cheese sometimes ended too far outward. | Curves were made more closed and centered. |

</div>

The most helpful improvements were lowering speed for better detection timing, adjusting PID, using steering confirmation, improving the color sensor position, and making the curves more closed.

## ❀ 3.5.18 Current Remaining Problems ────୨ৎ────────୨ৎ────

<div align="center">

| Remaining Problem | How It Appears | Why It Matters |
| :--- | :--- | :--- |
| **Curve sometimes starts late** | Cheese turns after the ideal moment. | Late turning can reduce space for recovery. |
| **Curve is sometimes too open** | Robot exits farther outward than desired. | Exterior-wall risk increases and the next obstacle becomes harder. |
| **Recovery after curve + obstacle** | Robot does not always become straight again quickly. | Camera view for the next obstacle becomes worse. |
| **Occasional wall contact** | Exterior wall contact can still happen. | Wall contact can ruin alignment and speed. |
| **Missed curve count** | Parking behaves strangely. | Parking depends on accurate curve progress. |

</div>

The main focus now is making Cheese turn slightly tighter while keeping recovery smooth and avoiding exterior wall contact.

## ❀ 3.5.19 Corner Handling Risk Map ────୨ৎ────────୨ৎ────

<div align="center">

| Risk | Possible Effect | Current Response |
| :--- | :--- | :--- |
| **Color sensor misses one line** | Curve count becomes wrong. | Lower sensor position, color grouping, and sequence logic. |
| **Curve count is missed** | Parking activates late or behaves strangely. | Use opposite-color pairing and curve cooldown. |
| **Robot turns too late** | Wide curve and poor exit position. | Tune steering response and approach speed. |
| **Curve is too open** | Robot gets closer to exterior wall. | Make curves more closed and centered. |
| **Recovery is slow** | Robot reaches the next obstacle at a bad angle. | Tune PID recovery and wall protection after curves. |
| **Battery is low** | Motors react weaker and curves become less consistent. | Test with charged battery before final runs. |

</div>

This risk map shows why corner handling affects the whole robot. A small curve problem can become a parking problem, a wall problem, or an obstacle problem later in the run.

## ❀ 3.5.20 Testing Plan for Corner Handling ────୨ৎ────────୨ৎ────

Corner handling should be tested separately before running the full obstacle challenge.

<div align="center">

| Test Stage | What to Test | Success Condition |
| :---: | :--- | :--- |
| **1** | Color sensor reading | Blue and orange are detected reliably. |
| **2** | Two-color sequence | `BLUE → ORANGE` and `ORANGE → BLUE` count one curve. |
| **3** | Cooldown behavior | One physical curve does not create two counts. |
| **4** | Steering confirmation | The counter only accepts a curve when steering behavior supports it. |
| **5** | Single corner movement | Cheese cuts the curve without hitting the inner or outer wall. |
| **6** | Corner exit | Robot returns toward the center after the curve. |
| **7** | Corner + obstacle setup | Robot exits the curve aligned enough to detect the next pillar. |
| **8** | Full Open run | Robot completes 12 curves and parks correctly. |
| **9** | Obstacle interaction | Robot curves, avoids, and recovers without carrying the pillar. |
| **10** | Repeatability | Multiple runs behave similarly with a charged battery. |

</div>

This testing order prevents the team from changing the wrong subsystem. For example, if parking fails because a curve count was missed, the team should check the color and curve counter first, not the final stop code.

## ❀ 3.5.21 Current vs Legacy Corner Handling ────୨ৎ────────୨ৎ────

<div align="center">

| Area | Earlier Behavior | Current v4 Behavior |
| :--- | :--- | :--- |
| **Curve reliability** | Less consistent at the beginning of development. | Mostly stable in Open Challenge. |
| **Color detection** | More affected by sunlight and sensor height. | Improved by lower sensor position and better color interpretation. |
| **Curve count** | Could fail and affect parking. | More reliable due to two-color sequence, cooldown, and steering confirmation. |
| **Curve shape** | Could be too wide or poorly timed. | More closed than before, but still being improved. |
| **Obstacle interaction** | Robot could detect obstacles but still carry them. | Detection and movement are connected, but recovery still needs calibration. |
| **Recovery** | Less predictable after curves. | Better, but still sensitive after curve + obstacle combinations. |

</div>

The current system is stronger because corner handling is not treated as one isolated turn. It is part of a full navigation chain.

## ❀ 3.5.22 Why Corner Handling Matters for the Whole Robot ────୨ৎ────────୨ৎ────

Corner handling affects several major robot systems at the same time.

<div align="center">

| Connected System | How Corner Handling Affects It |
| :--- | :--- |
| **Open Challenge navigation** | Good curves help Cheese complete laps smoothly. |
| **Obstacle Challenge** | A centered curve exit improves camera view and obstacle approach. |
| **Wall safety** | Wide curves increase risk near the exterior wall. |
| **Curve counter** | Correct corner detection keeps the internal progress state accurate. |
| **Parking** | Parking activates based on the completed curve count. |
| **Repeatability** | Consistent curves make the full run easier to reproduce. |

</div>

This is why improving corners is one of the team’s most important tuning priorities. Better curves do not only improve turning; they improve the entire run.

---

## ❀ Corner Handling Summary ────୨ৎ────────୨ৎ────

Cheese v4 handles corners through a structured color-based sequence. A curve starts when the color sensor detects the first valid floor marker and is completed when the opposite color appears within the allowed time window. Steering confirmation and cooldown protect the counter from false or repeated curve events.

The current corner handling is strong enough for Open Challenge runs and has improved compared with earlier versions. The robot now crashes less, turns more closed than before, and centers better between obstacles. However, the system is still being calibrated because curves can still be too wide or too late, and recovery after a curve plus obstacle avoidance is still one of the hardest parts of the robot.

<p align="center">
  <strong>Final interpretation:</strong><br>
  Cheese does not treat a corner as a single steering action. It treats each corner as a controlled sequence of color detection, steering confirmation, curve counting, movement correction, and recovery.
</p>
